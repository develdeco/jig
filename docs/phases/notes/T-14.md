## The naming rule

A slice's `workspace:` in `slices.yaml` is read against the project's repos:

| Project | Slice writes | Means |
|---|---|---|
| one repo | `server` | that workspace id of the repo, as it always was. A project of one repo never reads a slash: `app/web` is the bare id `app/web` |
| several repos | `api/server` | workspace `server` of repo `api`. Taken when the text before the first `/` is the name of one of the project's repos (`ready.SplitWorkspace`) |
| several repos | `server` | the one repo whose manifest declares `server` |
| several repos | `lib`, declared by `api` and `web` | **ambiguous**: owned by no repo, a validation problem (below). It was "the first repo of the project owns it, with a note" |
| several repos | `stray`, declared by none | unplaced, owned by no repo, a validation problem |

- A repo's name is `project.Repo.Name()` (the orchestrator marker's repo name, the
  folder's name by default).
- No new field in `slices.yaml`; the repo is part of the workspace text.
- A manifest finds the workspace of a slice with `Manifest.WorkspaceIn(repo,
  written)`: an id the manifest declares exactly as written wins (so a bare id
  with a slash in it still resolves), else the `<repo>/` in front is taken off.
  A workspace written for another repo is not found there.
- `ready.Place` gives, for each workspace as written, the repo (`Placement.Repo`,
  `ready.Unplaced` = `?` when no repo owns it), the id in that repo's manifest
  (`Placement.ID`), the bare ones nobody declares (`Unplaced`), the bare ones two
  repos declare (`Ambiguous`) and which repos those are (`Declared`).

## `jig validate`

Every repo's manifest is read from its mapped clone (`ready.ProjectRepos`), from the
orchestrator or from inside a clone. Problems, each one line in the
`VALIDATION_ERROR` help:

- `slice s: ambiguous workspace "lib": repos api and web declare it; name its repo, as api/lib or web/lib`
- `slice s: workspace "stray" is declared by none of the repos (api, web): name its repo, as <repo>/stray` (plus `; the manifest of docs could not be read` for a repo with no clone or no manifest)
- `slice s: workspace "server" not in the manifest of repo web` (a project of one repo keeps `slice s: workspace "x" not in manifest`)
- `slice s: oracle "lint" is not in the manifest of repo api (repo web declares it)`: an oracle name that only another repo's manifest has. A name nobody declares is a literal command and is not judged, as before. The empty-oracle check is unchanged.
- `no machine-mapped clone for repo "docs"`: told once, for a repo a slice builds in. A project of one repo is asked for its clone as before, slices or not.
- `repo web: manifest resolve failed: ...`: any repo with a clone whose manifest does not resolve (a project of one repo keeps `manifest resolve failed: ...`).
- The ticket's recorded branch is checked against every repo's target, since it has one name in each (`validateTicketBranch`; it used the first repo's).

## `jig context`, `jig claim`

- `jig context` names the slice's repo and clone (`repo:`, `clone:` in the context
  block and `repo`, `clone` in `--json`), only in a project of several repos, and the
  oracle command is resolved from the manifest of that repo's clone. Run from another
  repo or from the orchestrator, the help says `Slice s builds in repo r: work in
  <clone> (this directory is in x)`.
- `jig claim` binds the slice to its repo: the start point (`start.<repo>.sha`) is
  recorded for the slice's repo, from its clone, wherever the claim is made; the
  claim block gains `repo:` and `clone:` (several repos only) and the same help line.
  A claim from the wrong repo is not refused, it is told where to work.
- Both use `sliceHome(w, slice)` (cmd/jig/ticket_repos.go).

## Verification of a commit

- `cmd/jig/verify.go` `verifyRepo`: the repo is the one locate found around the
  working directory, else the one whose mapped clone is `--repo-dir`, else the
  project's only repo. A project of several repos with none to go by is a
  `VALIDATION_ERROR` ("cannot tell which repo of the project the commit is in",
  asks for `--repo-dir` or a run from inside the clone). It used to be the first repo.
- `verifySliceRepo`: a slice of another repo than the commit's is refused
  (`slice server of JIG-1 builds in repo api, but this commit is in repo web`, with
  the clone to commit in). Slices no repo owns yet are not refused.
- `internal/observe/commit_slice.go`: `sliceOf` passes over a trailer or a claimed
  slice that builds in another repo, so the hook that sees a commit starts no
  verification of it; `repoAndTarget` gives the located repo and its target, the only
  repo of a project of one, and no target (rather than the first repo's) for a
  repo the project does not list.
- `internal/verify/run.go` runs the oracle of the workspace the slice names in the
  manifest of the commit's clone (`WorkspaceIn`).
- `internal/correct/scope.go`: `Scope` and `WorkspacePaths` take the repo's name, so
  the scope check of a commit reads `api/server` as that repo's `server`
  (`correct.Input.Repo`, set from `Where.Repo`).
- `openLocatedStore` (cmd/jig/here.go, the hooks' store opener) completes the config
  with the repos of the marker (`project.LoadConfig`, as `locateStore` does for a
  verb); a v3 store lists none itself, so the hooks saw no repo in an orchestrator.

    code: MULTI_REPO_NOT_YET

## Decisions I took

1. **The repo is part of the workspace text, split on the first `/` against the
   project's repo names**, and only in a project of several repos. A project of one
   repo reads every workspace as a bare id, so nothing it has changes.
2. **An ambiguous or unplaced bare workspace belongs to `?`**, not to the first
   repo: `next` groups it under `?`, verify does not turn it away, validate refuses it.
3. **Start point = `origin/<target>` per repo**, a `start` column and key in `jig next`,
   not the recorded `start.<repo>.sha` (claim records that).
4. **Oracle check across repos is by name**: a name only another repo declares is a
   problem; a name nobody declares stays a literal command (the manifest cannot tell a
   typo from a command, and no phrase is guessed at).
5. **Claim from the wrong repo warns by help text, not a refusal**: the person or agent
   may be in the orchestrator on purpose.
6. **The refusal counts repos the slices resolve to**, so it needs no clone for a
   qualified workspace; a bare workspace needs the clone to be placed, and with none it
   counts for none (validate says the clone is missing).
7. **Branch against every target**: the ticket's branch has one name in all repos.
