# Gate reviewer: jig owns bookkeeping, never judgment

The gate reviewer rests on three ideas carried in from earlier review work: review in incremental rounds rather than one pass at the end, bundle findings mechanically rather than by judgment about their content, and put every judgment call to a person at one named seam. An earlier branch (PR #8) kept that vocabulary but replaced the mechanism with rules in five places: a hand-made `class` list (typo, dead code, behavior, security, ...) stood in for the model's own judgment of who acts on a finding; the reviewer had to write one closure per open finding, with a miscount failing the round; a clean result carried no evidence of what was actually read; a repeat of a dismissed finding was matched by normalizing and comparing its title text; and the eval corpus's gold was hand-written cases matched by a per-case title regex, widened case by case as reviews drifted from it. Each of these decides something - who should act, whether a problem recurred, whether two findings are the same - by pattern-matching the model's prose or by a jig-side rule standing in for a judgment the model or the human should make.

This rework replaces every one of them without adding a new special case: `action` (fix, ask, note) is the reviewer's own judgment, checked only for being one of three known values; identity across rounds is carried only through the reviewer's own `prior` field, never inferred from title text; a result must name every file it read (`reviewed_paths`), and an open finding only clears when its file was actually covered; a dismissed finding stays dismissed forever once `prior` names it, with no auto-dismiss heuristic beside it. What stayed unchanged from PR #8: the disk contract itself (`review.json` in, `result.json` out), strict structural parsing, the read-only guard, the gate-lease restore points, `reviewed_sha` scope anchoring at the merge base, and fix slices as the only way a finding turns into work - review has no back edges.

One more place was cut outright, with nothing standing in for it: `rung: cheapest`, which pinned mechanical fixes to the cheapest model and overrode a staircase that already starts there. The reviewer-eval title-pattern matcher was not cut the same way - its gold cases and phrasing tables grew every time a real review's wording drifted from the pattern, so a later eval rework replaces it with a single generic matcher whose gold comes from what humans actually decided at the triage seam (a kept ask or accepted fix is a true positive, a dismissal is a false positive, a triage addition is a miss, and a finding no human ever saw is unlabeled and pending), not from a per-case regex.

An `ask` nobody has decided never clears on its own. Coverage clears an open finding because the reviewer looking again and reporting nothing is evidence about the code; an ask is not a claim about the code but a question put to a person, and the reviewer reporting nothing says nothing about it. The moot-question worry is real but is answered by offering the ask again every round rather than by dropping it: a person who thinks it moot dismisses it in one keystroke, and that dismissal is recorded. Clearing it automatically buys that convenience at the price of the one thing the seam exists for - an unattended run would drop the question, report the round clean and point at publish, and the ticket would ship with the decision never made.

The reviewer's own label cannot retire an ask either, for the same reason and by the same rule a dismissed finding keeps its status: once the status is `asked`, a later occurrence replaces the finding's text, file, line, action and risk, and only a person changes the status. Both halves are one invariant - nothing the reviewer reports moves a finding out of `asked` - and a status that this round's label could overwrite would be no invariant at all.

One path does move an ask without a person, deliberately and on the record: with `--yes`, or with no terminal to prompt at, triage keeps every ask whose build target already resolves in full, a workspace and an oracle, and marks it `triage: auto` rather than `human`. What jig refuses to do unattended is decide an ask it cannot build - that one stays `asked` and holds the run. So the invariant above is about what a reviewer's report can do, not about what an operator can ask for by passing `--yes`.

What this buys an unattended run at this stage is a stop, not a park: the round is not clean, `jig gate` exits 2, and the ask is listed for whoever comes back to it. An ask is deliberately not yet a parked question in the builder's sense, with a `questions.yaml` entry and an `--answer` that clears it; that is its own change, and nothing here should be read as claiming it already ships.

A `note` on a recurring finding does not reset its identity, deliberately either: a noted finding is not outstanding work - it never blocks clean, and its file is not forced into `must_review` - but it stays a citable `prior` target (carried in review.json's `open` list, labeled `note`) so the recurrence count set on its first occurrence survives being noted in between. Without this, alternating `fix` and `note` labels on the same underlying problem would silently reset the count every time the label flips, defeating the recurrence bound - jig's stall concept applied to review, the same failure surviving a fix slice twice calling for a human decision instead of a third attempt - exactly as effectively as a title-text auto-dismiss would have, just through the opposite door.

Six more places were considered and left for later, each recorded so a later PR doesn't have to re-derive why:

- **Recording the files a reviewer session actually opened,** from the headless backend's own PreToolUse hook, instead of trusting the reviewer's own `reviewed_paths` claim. Stronger evidence, but it only works for the headless backend; revisit once headless runs for real.
- **A model judge for "is this the same problem as a dismissed finding".** The reviewer already judges this itself, via the dismissed list it's given each round; a repeat it fails to recognize reaches the human instead of being silently dropped, which is the safer failure mode.
- **Proving a fix red-then-green** with an oracle written specifically for the finding. For now, the next round's review of that file stands in as the proof.
- **Review ignore patterns for generated files,** deferred until a real diff actually needs them.
- **Automatic retry of an invalid reviewer result.** A `REVIEW_INVALID` round still fails loudly and the operator reruns it by hand.
- **`staircase.InvariantRE`,** a keyword regex that feeds the invariant floor. It's the same pattern-matching-as-judgment anti-pattern this ADR is about, but it lives outside the reviewer, so it gets its own follow-up rather than riding along with this one.
