# Headless permission model

A headless session is `claude -p`, where nothing can be approved interactively: every tool call is either granted up front or denied. jig runs it in `dontAsk` permission mode, so anything not granted is denied rather than prompted, and grants three things. The shell and file-read tools (Bash, Read, Glob, Grep) are granted only by the allow decision of the PreToolUse screen hook (`jig _screen`, run in exec form with no shell in between); every dispatch jig makes is screened, and an unscreened one, which only a test makes, gets those tools through plain allow rules instead. The file-edit tools (Edit, Write, NotebookEdit) are granted by path-scoped permission rules: anywhere in the lease worktree, plus the one result file the dispatch names, and nowhere else in the store. The screen still denies credential-shaped paths among them. Everything else - web access, subagents, skills, scheduling, MCP servers - is absent from the session (`--tools`, `--strict-mcp-config`). The rules and the hook travel in one inline `--settings` object, so they load together or not at all, and no settings file lands in the lease for a build's `git add -A` to sweep into a commit.

Granting through the screen is not by itself fail-closed, which is why jig proves the screen before it starts one. Claude Code treats a hook it cannot launch, or one that times out, as no decision at all, and its own read-only classifier still allows part of the shell (`echo`, `ls`, `git show`, `git log -p` and their like) with no rule from jig involved. So a screened session whose hook is missing, quarantined or broken would read the machine with nothing reporting that the screen was gone. Before each screened dispatch, jig runs the hook once with a call the screen must deny - a push - and refuses the dispatch (`SCREEN_UNAVAILABLE`) unless it comes back denied. One process per dispatch turns four silent states (missing, non-zero, no decision, wrong decision) into one loud one. It binds the start of a session, not its whole life: a hook that dies mid-session is not caught, and what the session keeps in that case is the CLI's read-only classifier, not jig's grant.

The screen decides which arguments of a tool call name files from the tool itself, not from one shared key list, because tools disagree: `Grep` filters with `glob`, `Glob` selects with `pattern`, and a credential file named in either is read out whole while a `Read` of the same path is denied. A tool the screen has no entry for is denied rather than judged on a guess, so a tool added to the session's surface is added here deliberately. It judges the literal argument and what that argument resolves to, because a spelling is not a location: a symlink in the lease pointing at `~/.aws`, or a search root that is a credential directory rather than a credential file, are the same read by another name. This is a denylist of credential locations, not confinement: a content search over an ordinary directory that happens to contain a `.env` still returns it, and only a real sandbox would change that.

The lease's own settings do not load (`--setting-sources user`). Project and local settings live inside the lease worktree, which is the content under review: a `.claude/settings.json` committed on the ticket branch would otherwise run its own PreToolUse hook on the operator's machine, outside everything jig screens, and a `.claude/settings.local.json` could grant edits anywhere on the filesystem. The operator's own user settings still load, deliberately: dropping them would drop their deny rules and hooks, which narrow the session at least as often as they widen it. The project source also carries the lease's `CLAUDE.md`, which the repo is supposed to give its sessions, so jig passes that file itself with `--append-system-prompt-file`. The line is capability against instructions: a settings file decides what a session may do, and must not come from the code under review; `CLAUDE.md` only says how the repo works, which is the repo's to say. Imports inside it are not resolved, since jig passes the file's own text.

This binds later work: a tool a session newly needs joins that surface deliberately, granted either through the screen (`screen.Granted`) or through a path-scoped rule, with its file-selecting arguments named to the screen, and a new backend with a tool-call surface needs an equivalent guard or documents the gap, as `herdr` does today. The model is not a sandbox: a granted shell can still write outside the lease or reach the network, `Read`, `Glob` and `Grep` reach the whole filesystem with only the credential denylist in the way, and the operator's own Claude Code settings still apply on top - their deny and ask rules narrow what jig grants, and their allow rules can widen it. A session is bounded in time (`JIG_HEADLESS_TIMEOUT`, 90 minutes by default) so a wedged CLI or hook ends as a failure rather than a run that never returns. It is also a contract with whichever CLI is installed, so `JIG_LIVE_CLAUDE=1 go test ./internal/session -run Live` checks it against that CLI through a local mock of the Messages API, with no credentials or network.

The `headless` backend is not a security boundary, and no patch to the credential denylist makes it one: the backend runs an unconfined shell with the operator's own rights, and the screen judges one token at a time before a shell ever gets to interpret it. A glob (`.a*s/credentials`) or a shell variable (`D=.aws; cat $HOME/$D/credentials`) still names the same file once the shell expands it, after the screen already judged the unexpanded token; a junction or a hard link resolves to a target `filepath.EvalSymlinks` cannot see, so the check falls back to the literal spelling and lets it through; and a search root named one directory above a credential folder is not itself credential-shaped, while the tool it is handed to still reads everything beneath it. Three review rounds patched around this same shape in turn - a glob, then a junction, then a parent directory - and each patch closed the instance without closing the class, because the class is "an unconfined shell can always find another spelling," not a missing pattern. The screen keeps doing what it is actually good at: catching an accidental credential read, stopping a disguised `git push`, and denying a plainly spelled credential path so an honest session does not stumble into one. Real confinement - a container, a separate OS user, or a `HOME` with no credentials in it - is the fix for the rest, and it is a separate future change, not a bigger denylist.

This round also closed holes in what the model already claimed for itself, distinct from the denylist question above. The lease's `CLAUDE.md` is now read from its HEAD tree through `internal/gitx`, not the working tree, so a symlink or hard link a screened session leaves behind cannot carry an outside file into the next dispatch's system prompt; a blob over the cap refuses the dispatch instead of forwarding an unbounded read every time (`leaseMemory`, `leaseMemoryCap`). A network share or a Windows device path (`\\host\share\...`, `\\?\...`) is judged by its literal spelling alone and never resolved: calling `filepath.EvalSymlinks` on an unroutable UNC address was itself a cost the screen was paying on the ticket's say-so, tens of seconds per fresh address, before it ever reached a verdict (`isNetworkOrDevicePath`). A tool call the screen cannot read - a missing or non-string Bash `command`, a required path argument that is absent, or any path argument shaped as something `SecretPath` cannot compare (a number, an object, null, a list holding a non-string) - is now denied outright instead of let through by the previous fail-open default (`ToolCall`, `requiredPathArg`). And the session bound now says what it actually enforces: the process tree is killed on `Cancel`, `WaitDelay` stops waiting on a child that outlived the CLI and still holds the pipes, and the timeout message names both the bound and that drain instead of only the shorter number.
