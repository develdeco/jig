# Headless permission model

A headless session is `claude -p`, where nothing can be approved interactively: every tool call is either granted up front or denied. jig runs it in `dontAsk` permission mode, so anything not granted is denied rather than prompted, and grants three things. The shell and file-read tools (Bash, PowerShell, Read, Glob, Grep) are granted only by the allow decision of the PreToolUse screen hook (`jig _screen`, run in exec form with no shell in between); every dispatch jig makes is screened, and an unscreened one, which only a test makes, gets those tools through plain allow rules instead. Claude Code treats a hook that cannot launch or times out as no decision at all, so a screen that only ever denied would fail open, running every command unscreened; a screen whose allow is the grant fails closed - no screen, no shell. The file-edit tools (Edit, Write, NotebookEdit) are granted by path-scoped permission rules: anywhere in the lease worktree, plus the one result file the dispatch names, and nowhere else in the store. The screen still denies credential-shaped paths among them. Everything else - web access, subagents, skills, scheduling, MCP servers - is absent from the session (`--tools`, `--strict-mcp-config`). The rules and the hook travel in one inline `--settings` object, so they load together or not at all, and no settings file lands in the lease for a build's `git add -A` to sweep into a commit.

This binds later work: a tool a session newly needs joins that surface deliberately, granted either through the screen (`screen.Granted`) or through a path-scoped rule, and a new backend with a tool-call surface needs an equivalent fail-closed guard or documents the gap, as `herdr` does today. The model is not a sandbox: a granted shell can still write outside the lease or reach the network, and the operator's own Claude Code settings still apply on top - their deny and ask rules narrow what jig grants, and their allow rules can widen it. It is also a contract with whichever CLI is installed, so `JIG_LIVE_CLAUDE=1 go test ./internal/session -run Live` checks it against that CLI through a local mock of the Messages API, with no credentials or network.
