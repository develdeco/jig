# Session-dispatched gate reviewer

`jig gate` now dispatches a real reviewer session instead of only re-running oracles: the reviewer reads `review.json` (the brief, slices and journal paths, every finding still open across earlier rounds, and every cumulative dismissal), reviews the ticket branch's diff against the brief without editing anything, and writes `result.json` with classified findings. Findings split into two classes: mechanical (typo, dead code, doc gap, formatting) bundles into one fix slice per workspace, pinned to the cheapest staircase rung unless the ticket's invariant floor overrides the pin; intent (behavior, correctness, security, design) becomes its own fix slice, built at whatever rung the staircase selects like any other slice - nothing pins it to the gate's own model. A human, or `--yes`, triages the open findings before any slice is synthesized - review has no back edges, so a finding is either dismissed for good or becomes forward work, never a comment left sitting outside the frontier.

Rounds are incremental: round 1 reviews the full diff against the merge base of the target branch and HEAD (falling back to the ticket's recorded start sha only when that lookup fails, and only if the start sha is still an ancestor of HEAD - a rebase onto an advanced target, or a `--branch` branch cut from a newer main, can leave the start sha an ancestor while the merge base has moved, so the merge base is checked first). Once a round's `reviewed_sha` is a real ancestor of the next round's HEAD, that next round reviews only the delta since it. Anything that breaks that anchor - a missing prior round, a rebase, an unrelated repo - falls back to a full review rather than trusting a stale or unrelated base.

Every prior open finding needs exactly one closure - `closed` when the diff resolves it, `still-open` otherwise - or the result is `REVIEW_INVALID`: a missing closure, a duplicate closure for the same id, or a closure naming an unknown id all fail the round. The reviewer is told not to re-raise a `still-open` finding itself; jig carries it forward as a new finding in the closing round instead, copying its class, title, workspace, and detail (extended with the closure's note) from the original and inheriting the oracle of the fix slice the original produced, so the carried finding flows through auto-dismiss and triage exactly like one the reviewer raised fresh. A dismissed finding's normalized title (lowercased, whitespace collapsed) is checked by jig, not the reviewer, against every later round's findings automatically; a title that is identical after normalization is dismissed before triage ever sees it, but a reworded title is a different string and reaches triage again - the prompt's "never raise a dismissed finding again" is the only defense against that, backed by the cumulative dismissed list `review.json` sends every round.

The reviewer session is held to the same forward-only discipline as the rest of jig: before writing `review.json` or dispatching, jig force-resets the lease to a pristine `HEAD` (`git reset --hard` plus `git clean -fd`), which wipes any dirt a manifest oracle left behind just before the review as well as any leftovers from an earlier failed attempt on the same lease; after dispatch it requires the lease's `HEAD` to still equal that pristine head and its tracked tree to still be clean (untracked files are ignored, since the headless backend writes `.jig/settings.json`), rejecting the round (`REVIEW_INVALID`) if either moved. Either way - success, a rejected round, or a dispatch failure - the lease is force-reset back to pristine again afterward. But that restore runs only inside `Round`, as a `defer`: jig installs no signal handler, so a killed jig (a Ctrl-C, or a reviewer left running in its own workspace "for jump-in" after `prompt --wait` errors) never reaches it, and whatever the reviewer left behind - an untracked repro file, or in `--branch` mode a commit that moves the branch ref - stays in the lease. `Gate` itself restores the lease again, right after the lease is acquired and before any oracle runs: normal mode does `git reset --hard HEAD` (HEAD, since `fetchTicketBranchFromBuildLease` already force-updated the branch ref to the build lease's copy) plus `git clean -fd`; `--branch` mode requires `refs/remotes/origin/<branch>` to exist (`BRANCH_NOT_FOUND` otherwise, since `pool.Acquire` never resets an existing local branch and so would otherwise silently validate a branch missing on origin) then resets to `origin/<branch>` plus `git clean -fd` - the gate lease never commits, so it must always equal `origin/<branch>` exactly, never a stale local copy or a reviewer's abandoned commit. So the two restores together, not the post-dispatch one alone, are what keeps a reviewer's or a killed run's leftovers from ever leaking into a later round's oracles or into the reviewed code. `result.json` is parsed strictly (exactly one JSON object, a known verdict, non-empty titles, valid classes, closures naming only real prior findings) so a malformed or off-contract session result fails loudly instead of silently becoming "clean".
