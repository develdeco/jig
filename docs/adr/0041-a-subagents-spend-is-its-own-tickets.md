# A subagent's spend is its own ticket's, and a chart shows its spend

`spend` writes one cumulative line per session on the ticket the session is placed at, and the line sums the main transcript and every subagent transcript under it. That was right while a session worked on one ticket. [ADR 0037](0037-a-chart-is-run-from-the-main-session.md) made a chart run a main session with one build subagent per ticket, each in its own worktree. Every subagent's tokens then landed on the ticket the main session was placed at, or on none, and a subagent's stop wrote no line at all. The ticket a subagent built showed nothing, the ticket the main session sat on showed everything, and a ticket's budget was held against the wrong number.

A chart's run has a cost, and the person who asks for a run wants to see it. A sum over the chart's tickets is only right once each ticket holds what was spent on it.

## Decision

**A subagent's stop writes a spend line of its own, on the ticket the subagent is placed at.** The line is the `spend` line of the session with `agent` set: the parent's session id, the agent's id, and the totals of that agent's transcript alone. It is cumulative and written only when the total changed since the agent's latest line. The transcript is `<main transcript without .jsonl>/subagents/agent-<agent id>.jsonl`, derived from the main transcript's path and the agent id, as Claude Code lays them out; the hook payload's `agent_transcript_path` is not read, since each adapter reads one transcript key and a new field would touch all of them. A subagent placed at no ticket, or with no transcript yet, writes none. After it records, a subagent's stop hears the ticket's budget note like any other event. There is no new journal event and no schema bump.

**A line is kept by session and agent.** `spend.Key(session, agent)` is the session id for the session's own line and `session/agent` for an agent's. `Latest` keeps the newest line of each key, so a session and each of its agents are kept apart. `Totals.Sessions` counts distinct session ids and `Totals.Agents` the latest lines that are an agent's: a ticket whose only lines are a session's agents has one session and N agents. `jig status` and `jig budget` show `agents: N` after `sessions:` only when N is above 0, and the budget note ends "(1 session, 2 subagents)" in that case.

**The main session's line leaves out an agent that has a line of its own.** At its stop and its end the session sums the main transcript and the subagent transcripts of the agents that have no line of their own (`spend.FromSession`). An agent has one when the machine ledger holds a `hook` line of this session with outcome `stop`, that agent and a ticket, which is how a subagent's stop was placed. `spend` reads those lines back from the ledger, newest first, bounded as the observe core's memory is, only when the session has subagent transcripts, and it does not stop at the session's `session-start` line: a resumed or compacted session starts again under the same id, and its agents' lines outlive that. An agent with no such line (still running, crashed, placed at no ticket, a harness that sends no subagent stops) stays in the session's line, so its tokens are not lost.

**A chart's spend is a fold over its tickets' latest lines.** For each ticket of the chart, `journal.Read` and `spend.FromLines`, and the per-ticket totals are added by `spend.Sum`. It is done per ticket and not over all the lines at once, because one session writes lines on several tickets and `Latest` would keep only the newest of them. A ticket whose journal cannot be read adds nothing: a problem is a row of the chart, never a reason to hide it. `jig next <chart> --json` gains a `spend` object (`tickets`, `agents`, `tokens`, `input`, `output`, `cache_read`, `cache_write`, `usd`, `unpriced`), left out when no ticket has spend. `jig next <chart>` and `jig status <chart>` say it on one line in the verdict block, `spend: 31.2M tokens ($12.34) over 3 tickets with 2 subagents`, which ends `; no price for <a> and <b>` for models with no price.

**The chart screen shows it.** The Run panel ends with a `spend` row read from that object, `31.2M tokens · $12.34 · 3 tickets · 2 subagents`, which a short screen gives up with the briefs. A chart with no spend, or a jig that prints none, draws what it drew. The activity says "a subagent has spent ..." for a line that has an agent.

## Rejected alternatives

- **A spend field in the chart, or a journal of the run.** A second place that says what was spent, kept beside the lines the tickets already hold. [ADR 0037](0037-a-chart-is-run-from-the-main-session.md) records nothing of a chart run for the same reason, and the sum over the tickets' lines is derived at the moment it is asked.
- **The main session's line dropping every subagent transcript.** It would count no token twice, but a subagent that never stops, or that is placed at no ticket, would be counted nowhere. Dropping only the agents that have a line of their own loses no token.
- **Scanning every ticket's journal for agent lines instead of the ledger.** It would find the agents that have a line, but at the cost of reading every journal of the store at each Stop. The ledger holds exactly the stop that was placed, is machine-local as the subagents are, and is read backward only as far as it needs.
- **Reading `agent_transcript_path`.** The payload names the agent's own transcript, but each adapter reads one transcript key of its own, so using it would add a field to every adapter. The path derived from the main transcript is the layout Claude Code keeps.

## Consequences

- Amends [ADR 0037](0037-a-chart-is-run-from-the-main-session.md): "`spend` stays off a subagent's stop, whose transcript is the whole session's" no longer holds. A subagent's stop writes the spend of its own transcript, and the session's line stops counting it once it has.
- Lines written before this keep their meaning: a line with no agent is the session's, whatever it counted. There is no migration and no rewrite. A line written earlier counted its subagents, and the session's next line replaces it.
- An older jig build that reads a line with an agent keys it by session alone, so an agent's line could stand in for the session's until it is upgraded.
- Between a subagent's stop and the session's next stop or end, its tokens are on both tickets. The session's next line takes them out: lines are cumulative per key and the newest is right.
- Tokens a subagent spends after its last stop are counted at its next stop, or stay in the session's line if it never stops again.
- A subagent's tokens now count against the budget of the ticket it built, which also fixes a single ticket's budget when a subagent built it.
- `CONTEXT.md` changes in *Spend*. `ARCHITECTURE.md` changes in the `spend` note source, the chart standing paragraph and the `internal/spend/` row. The `chart` skill says the `spend` line is what the run cost so far.
