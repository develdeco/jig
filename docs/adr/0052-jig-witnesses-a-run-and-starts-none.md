# jig witnesses a run and starts none

[ADR 0032](0032-jig-attaches-to-the-harness.md) moved the moment green is proven from dispatch to the commit: git's post-commit hook and the harness's PostToolUse each started a detached `jig verify` worker, which checked the commit out in a worktree of its own under the jig home and ran the slice's oracle there. The worker was jig's own process, outside the harness's process tree, and that had costs. Go's build and module caches started cold in every lease. The Stop hook held an unattended agent while a worker ran, so the agent polled it. A run's result reached nobody until the agent looked. A harness that wanted to run, bound or cancel the tests could not: jig owned the process.

## Decision

**jig witnesses a run and starts none.** A commit starts no process of jig's. Git's post-commit hook and the harness's PostToolUse still write the ledger's `git-commit` line, and that is all. The builder runs `jig verify` itself, in its own shell and its own worktree, in the foreground or as the harness's background task, once the slice's work is committed. `jig verify` runs the slice's oracle there with `sh -c`, in the caller's environment, streams its output unfiltered and exits with the command's own code (125 when jig failed before the command started). jig adds no flag to the command, retries nothing, caches nothing and schedules nothing, and the harness owns time: a `--timeout` bounds the run only when asked.

**The run is recorded with everything needed to run it again by hand.** One `oracle` line holds the command, the directory, the flags and the `--` command as given, jig's own stamp, HEAD when the run started and when it ended, whether the tree was clean before and after, the outcome and the seconds, and the process tree's CPU time and peak memory. The line is the record whatever the run was.

**A run covers HEAD, or it covers nothing.** A run covers HEAD only when the tree was clean before and after, HEAD did not move, the command was the slice's own oracle and HEAD descends from the ticket's start sha. A covering pass marks the slice green and writes the `verified` line; a covering failure leaves it building. Any other run is recorded with an `uncovered` reason and changes no slice state, and every reader of verification state (`journal.VerificationState`, the built commits, the gate's reuse of a pass) skips it. Green is still what jig proved: the evidence is a run jig witnessed on a clean tree at an unchanged HEAD, which the builder cannot fake with a claim, only by running the real oracle.

**What goes.** The detached worker and its `--worker`, `--agent-id` and `--repo-dir` flags, `verify.Spawn`, the lease worktree under the jig home, the per-commit lock, the `verify-pending` line, the `verify-spawned` ledger line, the "existing verification" answer with its `--rerun`, `--wait`, the commit positional, the light substitution of a delta, the manifest's limit as a bound on the run, and the comparison of a failure's output with the lines of the last pass. The Stop hook no longer names or holds on a running verification: it says what it said of a commit with no recorded result (now `jig verify <T> --slice <S>`) and of uncommitted tracked files. The old lines stay readable (`workerlive`, `verify.LatestSpawned`, the manifest's `light:` key and the journal's `ran` and `reused_from` fields) for the work that removes the states built on them.

## Consequences

The mechanism of ADR 0032 that started the oracle on a commit is superseded; the rest of it stands, and so does the rule that green is what jig ran. A builder's tests run warm, in its own caches and under its harness's control, and its output is in front of it as it is produced. A harness that kills `jig verify` kills the oracle's process tree, as before. jig adds nothing to what a run costs; a fast or slow run is the project's tests, not jig's lease. The price is that a commit nobody runs `jig verify` for stays unverified: the Stop hook and `jig here` say so, and an unattended session is held back from stopping with it.
