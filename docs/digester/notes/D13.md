# D13: unattended without a launcher; retire `jig run`

Branch `dg/D13`, from the `digester` tip 14cdfdf (every other ticket merged; the
last digester merge). jig starts no coding session any more, and the binary
links no code that does. `jig run`, `jig solve` and the hidden `jig _screen`
are gone, with the frontier, the herdr backend and the skills that routed to
them. The tests that built a ticket by running it build it the way an agent
does: commits in the person's clone, verified by `jig verify`. `TestDigesterFlow`
is the PR's demo.

## Changed behavior

- `jig` with no arguments: the usage examples are `jig next T-1` and `jig claim T-1 --slice a`.
- `jig status` and every hint that said `jig run T-1` to work the frontier now say
  "Run `jig next T-1` to see what is ready, then `jig claim T-1 --slice <slice>` to take one"
  (one line, the wording `jig validate` already used). `ready.Requeue`'s no-brief refusal
  names `jig answer <T> <qid> '<text>'` where it named `jig run --answer`.
- `jig requeue T --from-brief-diff|--slice S`: unchanged flags and output.
- Unattended Stop (`cmd/jig/observe_publish.go`, note source `publish`): at a Stop, when
  `verifydeliver.ReadStatus` says the latest gate round is `clean`, a **person's**
  `publish-approved` names the head that round reviewed, and no `publish-done` exists, the
  source returns a note with `Enforce: true` whose text is "<T> is reviewed clean and a
  person approved publishing <sha12>: run `jig publish <T>`, which pushes the reviewed head
  and opens the pull request". `Status.ApprovedFor` is the last person-provenance approval;
  an agent's approval does not stand in for the confirmation a bare publish asks, so it does
  not count here either. The core's rule does the rest: an unattended session is refused
  once for the Ref `publish:<sha12>` (a `note-delivered` line, outcome `stop-block`), an
  interactive one is shown the text as a message, and a Stop with `stop_hook_active` after
  the refusal is silent. The source speaks at `KindStop` only, so no tool call or prompt
  pays for the read. Multi-repo: `ApprovedFor` is the last approval, so only that repo's head
  counts; approvals are not tracked per repo.

## Launched reviewer (deviation from the brief's wording)

The brief says to move the launched reviewer source into `internal/revieweval/launch.go`
"via `PrepareReviewRequest`, `session.Run`, `GateFinish`". The whole of
`reviewerGateSource.Round` could not move: about sixty call sites in the `verifydeliver`
tests drive it, and they cannot import `revieweval` (it imports `verifydeliver`). So:

- `verifydeliver` keeps the session-free part: `Launcher` (`Launch(Launch) error`,
  `Readable(file) bool`), `Launch` (ticket, round, worktree, request, result and recordings
  paths, model, effort, prompt), `NewLaunchedGateSource(Launcher) GateSource`, and
  `RoundInput.Readable` (nil: every recording is listed; a recorded round leaves it nil
  because the reviewing agent is under no screen of jig's).
- `internal/revieweval/launch.go` is the session link: `launcher{session.Backend}` maps a
  `Launch` to a screened `session.Dispatch` (slice `gate`, attempt = round, `ExtraReadFile` =
  the recordings list) and answers `Readable` with `screen.ToolCall("Read", ...)`;
  `reviewerSource(backend)` is what `runRound` uses. `launch_test.go` pins the mapping.
- `verifydeliver/launcher_test.go` holds a test copy of that mapping (`sessionLauncher`,
  `newReviewerGateSource`, which is what `NewReviewerGateSource` was to the tests). Its doc
  comment says why it is a copy.
- `GateFinish` is untouched: a launched round still ends in `Gate`'s `finish`, a recorded
  one in `GateFinish`; they share `checkReviewResult`.

`WSLPath` went with herdr; the scrub of a session's repeated paths still has to know the
WSL mount spelling (a session that runs in WSL on a Windows checkout sees it), so
`verifydeliver/hostpaths.go` has its own `wslMountPath` and `TestWSLMountPath`.

## The screen hook (deviation: not in the brief)

`jig _screen` was the PreToolUse hook program of a screened headless session
(`session.Options.ScreenBinary`), and the evaluation's live runs need it. The brief deletes
`screen.go`, so the handler moved:

- `internal/screen/hook.go`: `screen.Hook(stdin, stdout)` (the old `runScreen`); the three
  in-process tests moved with it (`hook_test.go`, same names).
- `testdata/fixture/screenhook/main.go`: a ten-line program that calls it. It is invoked as
  `<program> _screen` as before (the argument is ignored); the session tests, the opt-in
  `TestHeadlessLiveCLI` and the evaluation's live tests build it where they built `cmd/jig`.
  `session/screenhook_test.go` is the old `screen_binary_test.go` against it.
- `session.Options.ScreenBinary` is required for a screened dispatch (the default of "this
  process, if it is jig" is gone: nothing but jig had it right). `TestHeadlessScreenBinary`
  still pins the refusal.
- `ARCHITECTURE.md`: `screen.Hook` is in the `internal/screen` row (`TestExportedSurface`
  pins the row to the exports), and the `cmd/jig` row loses `cmdScreen`. These two row edits
  are outside "rows of packages it deletes"; lint requires them.

## Skills

`skills/build` gained "Handing a slice to another agent": the rules the dispatch prompt
carried, as the text an agent puts in the prompt of a subagent it starts: work only in the
clone; the goal and the oracle; claim, then `jig context`; run only the tests that cover the
change, since jig runs the oracle on each trailer commit and returns a red run's tail;
commit, and leave no tracked change uncommitted; done when `jig here` shows the slice
verified, with no result file; when stuck, `jig ask`, and a brief that cannot be built or an
oracle that cannot pass is a question, not a retry; an environment that will not come up is a
note and a release; leave pushing to publish and never answer your own question. It also says
`--unattended` holds the session back at Stop. 84 lines, 5.5 KB (budget 100 and 6 KB).

## Tests

`e2e/digester_flow_test.go` `TestDigesterFlow` (about 16 s; run it with `-v` for the
transcript) is the design's "Final gates" flow. Notes on it:

- Step 6 uses `CommitScenario` and waits for the `verify-spawned` ledger line git's global
  post-commit hook writes; the PostToolUse hook fired after it must leave one spawn per commit.
  Stop is asked while slice a's verification still runs, before that hook, so the race is
  the worker's start against one hook process.
- `ask --wait --timeout 1s` is the exit 2; `answer --as person`; the answer reaches the
  session at its next UserPromptSubmit. The silent Stops come after a prompt has delivered
  the verification outcomes, since an outcome not yet heard is shown at Stop.
- The person's approval of the head is appended to the journal by the test (`publish-approved`,
  provenance `person`): an e2e process has no terminal, so `jig publish --approve` would record
  `agent`; the TUI's `p` key and a terminal record exactly this line. Stop then refuses once
  with the publish command, and a Stop with `stop_hook_active` after it is silent.
- `githubRemote(t, fx, env)` (new in `gate_recorded_test.go`; `githubClone` calls it) sets
  the fake gh and the `insteadOf` on an env that already has a git global config. Calling
  `withGitGlobal` a second time would drop the `core.hooksPath` that `jig setup` installed.
- It asserts the changelogs, `ledger.md`, `platform/contract-index.md` and the PR body a
  publish leaves (what `TestEndToEndTwice` covered), that the product repo's tree is
  unchanged, that no `*.slice.json` exists under the test's tree or jig home, and that `jig run`

## ADR impact (for D1)

- ADR 0008 (headless permission model): the binary has no `_screen` and starts no headless
  session. The screen and its hook remain for the reviewer evaluation, run from
  `testdata/fixture/screenhook`: superseded for the product, kept for the evaluation.
- The ADRs about dispatch (builder sessions, the staircase, fix turns, session persistence,
  the herdr and WSL path spelling) describe code that is gone. ADR 0032 should say the build
  is an agent's, verified by `jig verify`, and that the prompt's rules are in `skills/build`.
- For ADR 0032, what holds an unattended session back at Stop: a verification running or a
  tracked file uncommitted, a failed oracle or a correction (enforced notes), and a ticket a
  person approved that is not yet published. An open question is shown and holds nothing.
  Each is refused once per fact.
