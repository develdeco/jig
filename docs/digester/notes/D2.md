# D2: writer branches, the claims log, the driver, journal appends

Branch `dg/D2`, from the `digester` tip bdd8129 (S0, D19, D8, D17 merged), then
merged with 830b0b4 (D12, D9), 503f5c9 (D11), d1f00a9 (D10) and 28860c8 (D14,
the last digester merge). Decision 4 of the plan: a store can move to
**writers mode**, where each clone pushes only to a branch of its own and the
things no two writers may do at once (mint an id, drive a ticket) go through a
claims log on a branch of its own. A store that has not moved (**single-main
mode**) does what it always did. Journal appends are now provably safe across
processes, and `jig status` names the driver of a ticket.

## The mode switch

A store is in writers mode when it has a claims branch: `refs/heads/claims` in
the clone or `refs/remotes/origin/claims` as last fetched (`Store.Mode`, a few
file reads, no git process). Anything else is single-main, and nothing below
applies to it except what it says. `jig store migrate --writers` converts a
store; a clone made after that (any `git clone`) is in writers mode from its
first command. A clone made before it learns of the move when it next fetches
every branch, which `jig store migrate --writers` there does; until then it
keeps pushing main, which every writer still reads (the legacy branch).

In writers mode:

- The clone works on `writers/<name>` and checks it out by itself when it is on
  anything else (main in a fresh clone): the clone branch of that name if there
  is one, else one made from `origin/writers/<name>`, else one made from where
  the clone is.
- **Writer name** (`Store.Writer`): `git config jig.writer` in the store clone,
  else the host name, cleaned to lowercase letters, digits and single hyphens,
  at most 40 characters. A `jig.writer` with no letter or digit in it is a
  VALIDATION_ERROR. Two clones must not share a name.
- **Sync / pull** (`pullWriters`): `git fetch origin +refs/heads/*:refs/remotes/origin/*`;
  the clone claims branch follows `origin/claims`; the own-name check; then every
  other `origin/writers/*` and the legacy `origin/main` is merged in, in that
  order (main first, writers alphabetically). One `git for-each-ref` reads all
  the tips, so a Sync with nothing new is the fetch plus that.
- **Own-name check**: `origin/writers/<me>` already in HEAD is fine; HEAD behind it
  (another clone of the same writer pushed more) fast-forwards; neither is
  `WRITER_NAME_TAKEN` (exit 1), before anything is merged or pushed. The help
  names `git config jig.writer <name>`.
- **Rewrite rule**: the machine-local ref `refs/jig/seen/<writer>` (`_main` for the
  legacy branch; a `/` in a name becomes `+`) holds the tip last merged. A new tip
  that does not descend from it was rewritten: a Warn (`WRITER_REWRITTEN: ...`, in
  the output of the command whose Sync found it, every Sync until it is dealt
  with), no merge, no repair; the other writers still merge. The warning says how
  to accept a rewrite on purpose (`git update-ref -d refs/jig/seen/<key>`).
- **Merge**: a fast-forward when HEAD is part of the tip, else a merge commit by the
  person (`Store.identity`, D19) with `-m "jig: merge <branch>"`. Before a real
  merge the working `.gitattributes` is made `WritersAttributes` and committed
  ("jig: merge ndjson files by union") when it is still the plain
  `StoreAttributes`; any other `.gitattributes` is the owner own and is left.
  A conflict in any file but an `*.ndjson` aborts the merge and is `STORE_CONFLICT`
  naming the paths, the store back where it was.
- **Doubled lines**: the union driver keeps both sides of a hunk both sides changed,
  and when two writers have merged each other in turn the same line comes out
  twice (the test `TestWritersJournalsConvergeWithoutDuplicates` found it).
  After each real merge, every `*.ndjson` the merge touched is cut back so no line
  is in it more often than in the side that has it most (`dedupeLines`), and the
  unpushed merge commit is amended. Blank lines and line endings are left alone.
  Readers still must not assume time order: union reorders lines.
- **Push**: `writers/<me>` only, never main. `push` and `pushOnce` are the old
  ones with `cp.branch = writers/<me>`; a rejected push takes what moved the way
  Sync does (so the own-name check) and pushes once more.

`gitx.WritersAttributes` is `StoreAttributes` plus `*.ndjson merge=union`. The
in-process git (`gitx.Repo`) accepts either text (a merge driver converts no
content). It cannot walk a merge commit, so in a writers store every fetch and
push that meets one falls back to the git program (`ErrUseCLI`), as ADR 0011
already allows; commits stay in process.

## The claims log

No journal or ledger line is new; the one new line shape is the claims line,
and it is in no journal. One file, `claims.ndjson`, one JSON object per line:

```
{"ts":"2026-10-23T12:50:24.5193501Z","kind":"driver","ticket":"JIG-1","writer":"alice","session":"s-1","author":"Alice Person"}
```

| Key | Meaning |
|---|---|
| `ts` | UTC, RFC 3339 with nanoseconds |
| `kind` | `id` (an id or alias is reserved), `driver` (the writer drives the ticket), `release` (ends the same writer driver line) |
| `ticket` | the id reserved, or the ticket driven or released |
| `slice` | optional; the slice the claim was made for (nothing writes it yet) |
| `writer` | the writer name; empty on the lines of the root commit a migration writes |
| `session` | optional; the harness session |
| `author` | the name of the git identity that wrote it |

`store.ClaimLine`, `Store.Claims`, `AppendClaim` (a plain append, no decision),
`Driver(ticket)`, `ClaimDriver(ticket, session, take)`, `ReleaseDriver(ticket, session)`.
The driver of a ticket is its latest `driver` line that no `release` line from the
same writer has ended since.

- **Writers mode**: the log is alone on the orphan branch `claims`, which nobody
  checks out. An append reads the tip, builds blob, tree and commit with plumbing
  (`gitx.RunInput`: `hash-object -w --stdin`, `mktree`; then `commit-tree` with the
  D19 identity), moves `refs/heads/claims` with `update-ref new old`, and pushes
  it. A rejected push (the branch moved, or two pushes met at the ref lock:
  "incorrect old value") puts the local ref back, fetches, **decides again on the
  log as the origin has it**, and tries up to 5 more times with a short backoff. A
  push that fails any other way restores the ref and is `CLAIMS_NOT_PUSHED`: a claim
  is not a claim until the origin has it. The local claims branch is only a copy
  of the origin one; a copy that went past it is the unacknowledged line of a
  process that died, and is dropped at the next fetch. A refusal (DRIVER_HELD, id
  taken) is checked against the origin before it is given, so an old view never
  refuses anyone.
- **Single-main mode**: the same functions, backed by `claims.ndjson` at the store
  root on main, appended through `Store.Claim` (committed alone, pushed, undone and
  decided again on a rejection). A decision that needs no write takes no lock and
  asks git nothing.
- `jig store migrate --writers` carries the lines of an old root `claims.ndjson`
  into the new log in front of the id lines.

**Why the driver is in the claims log and not in the ledger** (deviation from the
ticket text, decision 4): the ledger is machine-local, and a driver is only
useful if another writer machine can see it.

## Ids

`Mint` in writers mode **reserves the id on the claims log before it makes the
folder**: `nextID` is one past the highest of the folders and aliases of the
store and the `id` lines of the log; the id line is appended; if the log already
holds that id (another writer got there first) the next is tried, up to 10 times;
a reservation the origin cannot take is `ID_NOT_CLAIMED`. `Claim` then commits
the folder on the writer branch and pushes it, unchanged. This is the brief
"reserve on claims first" with the undo-and-retry folded into `Mint`, where
nothing has been written yet, so there is nothing to undo. An id that was
reserved and whose ticket never landed stays reserved (a gap).

## Journal appends (`internal/journal`)

- `Append` takes the checkpoint lock and the journal file lock (`store.TryLock`, 30
  s) and **refuses without them**: `JOURNAL_LOCKED` instead of writing unlocked.
- The line is **one `O_APPEND` write** in place (no read-all, no temp file, no
  rename, so the file keeps its identity); a newline goes in front of it when the
  file ends mid-line.
- `Read` leaves out any line that is not a JSON object, blank ones included, so a
  torn line (a writer died, or one is being written) hides nothing. This is wider
  than "a torn final line": the next `Append` closes a torn line with a newline,
  which makes it a bad line in the middle.

## Verbs and flags

| Verb | Change |
|---|---|
| `jig store migrate --writers [--dry-run]` | moves the store to writers mode, or joins this clone to one another clone moved; takes neither `--map` nor `--to`; refuses a dirty store, a store not level with its origin (unless already in writers mode) and a store with no origin |
| `jig claim [T] --slice s [--take]` | takes the **driver** of the ticket for this writer after the conditions and before it writes; `DRIVER_HELD` (exit 1) when another writer drives it, with help `jig claim <T> --slice <s> --take`; `--take` also takes the ticket over. `--take` keeps its slice meaning |
| `jig claim --release` | releases the driver once no slice of the ticket is held any more by a claim made since this writer became the driver |
| `jig status <T>` | a `driver:` block (`ticket`, `writer`, `author`, `session`, `since`) between the status blocks and the help line, when someone drives the ticket (Order 100, name `driver`) |

`jig store migrate --writers` prints a `writers:` block (`writer`, `branch`,
`claims`: `to create` / `created` / `exists` / `joined`, `ids`, `carried`) and three
help lines. Steps: fetch every branch; make the claims branch if the origin has
none (root commit: carried lines, then one `id` line per ticket id and alias; a
lost race joins the other); check out `writers/<name>`; commit the union
`.gitattributes`; push `claims` and `writers/<name>`. Main is never pushed. It is
idempotent.

Codes: `DRIVER_HELD`, `WRITER_NAME_TAKEN`, `WRITER_REWRITTEN` (a warning),
`CLAIMS_NOT_PUSHED`, `JOURNAL_LOCKED`, `ID_NOT_CLAIMED` (now also for a reservation).

## Decisions and details a later ticket needs

- **A writers store is switched to by a ref, not a file in the tree**, so mode needs
  no read of a config and an old clone cannot be fooled by a stale checkout.
- `StoreAttributes` keeps its text (every new single-main store and the fixture write
  it); the union line is the new `WritersAttributes`. Deviation from the brief
  "StoreAttributes gains": changing the constant would change every single-main
  store.
- The same driver can run any number of sessions: a second session of the writer
  already driving writes nothing. Slice-level exclusion stays `SLICE_HELD`.
- Driver release counts only claims made since the writer became the driver; the
  claim lines of a driver it took the ticket from are not its.
- `Store.Writer()`, `PlanWriters()` and `MigrateToWriters()` are exported for
  `cmd/jig`; `gitx.RefExists` (new file `refs.go`) is what keeps `Mode` free of a
  process.
- The writers-mode fetch is `+refs/heads/*:refs/remotes/origin/*` with no prune:
  a deleted writer branch stays visible and merged.
- Branches named other than `main` as the legacy history are not merged; a store
  whose single-main branch was not `main` should be renamed first.
- Windows: concurrent `jig ticket new` in two clones lost a push to the claims ref
  lock ("incorrect old value provided", `[remote rejected]`), which is not the
  "fetch first" text; `claimsPushRaced` treats it as a lost race. `pushRejectedText`
  (single-main `Claim`) is unchanged.

## Deviations from the brief

- `Mint` reserves the id, not `Claim` (above); `claim.go` only gained a doc paragraph.
- `StoreAttributes` unchanged, `WritersAttributes` added (above).
- Extra beyond the brief: `ReleaseDriver` and the release in `claim --release`; the
  doubled-line cut after a merge; the re-check against the origin before a refusal;
  fast-forward of a clone only behind its own name; `PlanWriters` and `--dry-run`
  for `--writers`; `gitx/refs.go`; `journal.Read` skipping every bad line.
- `JOURNAL_LOCKED` uses a `wait` parameter (`appendWithin`) rather than a variable,
  because the lint forbids a test assigning a package variable.
- The Write and Edit tools refused paths in this worktree; files were written through
  the shell.

## Known limits

- Five e2e tests that wait for a detached `jig verify` worker (`TestHooksDriveVerify`,
  `TestVerifyFailPersistsSignature`, `TestVerifyHandCommitReusedByGate`,
  `TestEventsReadsHarnessRun`, `TestEventsFollowSeesHookVerification`) timed out
  after 3 minutes with an empty journal in one full run on this Windows host, on
  the **unmodified** digester tip bdd8129 as well as on this branch, and passed in
  the next full run of this branch (118 s for the whole package). The plan lists
  the job-object limit on detached workers as a risk; nothing in D2 touches the
  worker, so treat a repeat of it as that, not as D2.
- `jig status` does not sync, so the driver it names is the one as of this clone
  last fetch (any claim, ask, answer, note or ticket command syncs).
- A clone that has not fetched since the move is single-main until it joins.

## ADR impact

ADR 0032 (D1) can say: a store has two modes; writers mode (a `claims` branch) gives
each clone a branch of its own, merges the others read-only with a union driver for
NDJSON files, and keeps the one-at-a-time facts (ids, the driver of a ticket) in an
append-only log on its own branch that every writer pushes by compare-and-swap; no
writer ever pushes main or rewrites another branch, and a rewritten branch is
refused and reported, never repaired. ADR 0011 (the store runs git in process): the
store history is linear only in single-main mode; in a writers store the in-process
path commits, and fetches and pushes of a history with merges go to the git program.
The journal paragraph of the architecture: a journal is appended to in place, one
write under two locks, and a reader leaves out a torn line.
