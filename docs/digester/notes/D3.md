# D3: `jig here`, `jig next`, `jig map`, `jig ignore`

Branch `dg/D3`, from the `digester` tip 26b5642 (S0b and S0a merged). Locate is
the one place a directory becomes a project, and every verb now resolves its
store through it, so a clone that only carries a `jig.yaml` marker works as well
as a mapped one.

## Verbs

All four are registered from their own file's `init()` (Order 300 to 303) and
take their one positional anywhere among the flags (`parseWithPositionals` in
`here.go`: `jig next JIG-1 --json` and `jig next --json JIG-1` are one command;
`atMostOne` and `exactlyOne` check the count; D8 and later verbs can reuse them).

| Verb | Flags | Exit |
|---|---|---|
| `jig here [T]` | `--store`, `--slice`, `--session`, `--json`, `--explain`, `--no-map` | 0 whatever it finds; a VALIDATION_ERROR (2) for an unknown ticket, a store whose schema needs `jig store migrate`, or a bad flag |
| `jig next [T]` | `--store`, `--project`, `--topology`, `--json` | 0; 2 for an unknown ticket |
| `jig map <repo>=<path>` | `--store`, `--project` | 0; 2 for a repo the project does not declare, or a path that is not a directory |
| `jig ignore <path>` | `--remove` | 0 |

**`here`** prints, in order: a `here:` KV block (`project`, `how`, `kind`, `root`
(only when it is not `repo_dir`), `store`, `store_remote` (only when the store is
not cloned here), `repo`, `repo_dir`, `branch`, `ticket`, `ticket_how`, `title`,
`slice`, `slice_how`, `session`, `session_how`, `mapped: yes`; empty keys are
left out), a `nested[N]{dir}` table (orchestrators), then for a ticket in a
store `slices[N]{id,state,attempts,blocked_by,question}`,
`verified[N]{slice,commit}` (12-character shas, only when there are some),
`questions[N]{id,slice,question}` or `questions: none` (open ones only, the
body's first line), `pending_verifications[N]{slice,commit}` (only when there are
some), the blocks of every registered `hereSection` by Order, an `explain[N]:`
block with `--explain`, and one `help[1]:` line. Outside every project (how
`none`) it prints nothing and exits 0, `--json` and a positional included;
`--explain` alone prints the explain block. It never calls Sync, Push or the
mirror, and writes nothing but the machine-map entry of a clone it recognized
(`--no-map` turns that off).

**`here --json`** is one line, one object. Absent parts are omitted:

```
{"how","jig_home","cwd","project","kind","root",
 "store":{"path","remote"},"repo":{"name","dir","branch"},
 "ticket":{"id","how","title"},"slice":{"id","how"},"session":{"id","how"},
 "nested":[...],"mapped":true,
 "state":{"slices":[{id,state,attempts,blocked_by,question}],
          "verified":[{slice,commit,attempt}],
          "questions":[{id,slice,body}],
          "pending_verifications":[{slice,commit,since}]},
 "sections":{"<section name>": <that section's JSON>},
 "explain":[...]}            // only with --explain
```

`how` values: project `flag|marker|map-path|map-remote|store|none`; ticket
`arg|arg-alias|branch|branch-alias`; slice `arg|env|claim`; session `arg|env`.
`state` is present when the store is here and a ticket is named. A registered
section's `Blocks` follow the ticket's blocks in the text, and its `JSON` goes
under `sections.<Name>`, never into the top level, so sections cannot collide
with each other or with these keys.

**`next T`** prints `next:` (`ticket`, `title`, `state`, `branch`,
`distribution` when the marker has one), `blocked_by[N]{ticket,kind}` when it is
blocked, `ready[N]{repo,slices}` (one row per repo, slices joined by `+` in build
order) or `ready: none`, notes for workspaces no repo declares, `--topology`'s
`topology[N]{slice,workspace,repo,state,wave,blocked_by}`, and help: the
distribution advice (one repo: one session takes the set in order; several: one
session per repo can run in parallel, each repo's slices in order) then the
branch to create. The `state` is `done|blocked|ready|active|green|new`
(`ready.State*`). `--json`: `{ticket,title,state,branch,distribution,
blocked_by:[{ticket,kind}],ready:[{repo,slices}],unplaced_workspaces,
ambiguous_workspaces,topology:[{id,workspace,repo,state,wave,blocked_by}],
advice}`.

**`next`** prints `tickets[N]{id,title,state,blocked_by,ready}` in store order
(`blocked_by` is `JIG-1(merged)+JIG-2(stacked)`), then, only when two tickets'
local branches change one file, a `warning:` line and
`overlap[N]{repo,file,tickets}`, then help (the first ready ticket). `--json`:
`{tickets:[{id,title,state,blocked_by,ready}],next:[ids],overlaps:[{repo,file,
tickets,branches}]}`. A ticket is blocked while a blocker in its `ticket.yaml`
has no `publish-done` journal line (a blocker not in the store counts as
unpublished); a blocked or done ticket offers no ready slices.

**`map <repo>=<path>`** replaces `projects.yaml`'s clone entry for the repo of
the resolved project (`--project`, `--store`, else the directory), after
checking the project declares it. **`ignore <path>`** adds the absolute path to
`<jig home>/ignored.yaml` (`paths:` list); the directory and everything under it
is then none for Locate, whatever a marker, the map or a remote says. `--store`
still names a store explicitly. `--remove` takes only the path's own entry out.

## Resolution order (internal/locate)

`Locate(jigHome, cwd, Opts)` returns the first that answers:

1. `Opts.StoreFlag`: `HowFlag`. Errors when the directory has no readable
   `project.yaml`. The repo is the project's mapped clone that holds cwd, if any.
2. The ignored list: a cwd under an ignored directory (or a worktree of an
   ignored clone) is `HowNone`.
3. `project.FindMarker` walking up: `HowMarker`. A `jig.yaml` that decodes to
   none of `jig`, `project`, `store`, `kind`, `repos` is another tool's file and
   is passed over; one that is not YAML is an error. Store: the machine-map
   entry's `Store` if it is still a store, else a marker `store:` that is a local
   path holding one, else the sibling `<root>/../<project>-tickets` holding a
   `project.yaml` or `store.yaml`, else none (`Where.StoreRemote` = the marker's
   store, `StorePath` empty). Repo: for `project` and `member` the repo is the
   marker's directory (the clone, for a linked worktree); its name is the mapped
   clone there, else the project's only repo, else the repo whose remote is the
   directory's origin, else the marker's only repo, else the directory name. An
   `orchestrator`'s repos are `repos[].path` under the marker; the one holding
   cwd is the repo and `Where.Nested` lists those that exist.
4. The machine map by path: the longest clone (or project `root`) containing
   cwd, else the clone cwd is a linked worktree of (`gitx.TopLevel`, the
   `.git` file, `gitx.CommonDir`, `gitx.SameDir`).
5. The machine map by remote: cwd's `origin` against every mapped project's
   `project.yaml` repo remotes (`NormalizeRemote`: scheme, user, port, case,
   `.git` and trailing slashes do not matter; a Windows path equals its
   `file://` URL).
6. A store directory: cwd holds a `project.yaml` or `store.yaml`; or the git top
   level above it does and also has a `ledger.md`, `tickets/` or `platform/`
   (a lone `project.yaml` at some other repo's root is not a store); or the
   `<repo>-tickets` sibling `jig init --standalone` makes (the old fallback of
   `project.Resolve`, kept; it reads as `HowStore` with the repo set).
7. `HowNone`, no error.

A clone found by marker or remote (never by flag or store directory) is added
to `projects.yaml` on the spot through `project.UpdateMachine`, unless
`Opts.NoMap`, and only when the store is here: the project's `Store` when it has
none or the one it names is gone, its `Root` (marker directory; not for a
`member`), and each found clone when the repo has no clone or its clone's
directory is gone. A live mapping is never replaced, so a second clone of a
mapped repo is recognized (`map-remote`) and left unmapped. `Where.Mapped` is
true when the call changed the map; a failed write is an Explain line, not an
error.

Then, unless `Opts.StoreOnly`: the branch (`git symbolic-ref` in cwd when cwd is
a work tree of the repo, else in the repo's directory); the session (`Opts.Session`,
else `JIG_SESSION`); the ticket (`Opts.Ticket`, resolved through
`Store.ResolveTicket`; else `Store.TicketForBranch(branch)`; a branch whose id
two tickets claim binds nothing and says so in Explain); the slice (`Opts.Slice`,
else `JIG_SLICE`, else the session's latest `claim` line on the ticket, undone by
a later `release` line of the same session and slice).

`resolveStoreChecked` (main.go) now calls `locateStore` (`cmd/jig/locate.go`),
which asks for `StoreOnly`: no git call for the repo, branch or ticket, and none
at all when cwd is inside a mapped clone or holds a store. When Locate names no
store the verb refuses with the old `no jig store found for this directory`
message, or, for a marker whose store is only a remote, with the `git clone`
command to run.

## Explain strings

One line per step, in order. `<x>` is a value.

- `flag: --store names <path> (project <name>)`; `repo: <cwd> is inside clone <dir> of <repo>`
- `ignored: <cwd> is under <dir>, which `jig ignore` told jig not to track`; `none: <cwd> is not tracked`
- `marker: no jig.yaml from <cwd> up`; `marker: <file> names no project, store or repos; not read as a jig marker`; `marker: <file> names project "<p>" (kind <k>)`
- `store: <path> (machine map entry for <p>)`, `(the marker's store, a path)`, `(sibling of <dir>)`; `store: the machine map puts <p> at <path>, but no store is there`; `store: not cloned here; the marker's remote is <url>, expected at <sibling>`; `store: the marker names none and no sibling store is next to <dir>`
- `project: the store at <path> is named "<n>", not "<m>"`
- `repo: <name> at <dir>`; `repo: <cwd> is in the orchestrator itself, in none of its <n> repos`; `repo: <cwd> is inside <dir>, repo <r> of the orchestrator`
- `map-path: <cwd> is inside|is a linked worktree of <dir>, repo "<r>" of project <p>`; `map-path: no mapped clone holds <cwd>`
- `map-remote: origin <url> is repo <r> of project <p>`; `map-remote: <cwd> is not in a git work tree`; `map-remote: <top> has no origin remote`; `map-remote: origin <url> is no repo of a mapped project`
- `store dir: <cwd> holds a store`; `store dir: <cwd> is inside the store at <top>`; `store dir: <sibling> is the standalone store next to <dir>`; `store dir: <cwd> is not in a store`
- `none: <cwd> is not in a jig project`
- `map: recorded project <p> in the machine map (store <s>, <n> clone(s))`; `map: could not record project <p> in the machine map: <err>`
- `branch: <b> checked out in <dir>`; `branch: none checked out in <dir> (detached HEAD)`
- `ticket: <id> (arg|arg-alias)`; `ticket: <id> (branch <b>)`; `ticket: <id> (branch <b> leads with an earlier id)`; `ticket: branch <b> leads with no ticket of this store`; `ticket: branch <b> binds nothing: <err>`
- `slice: <s> (arg|env|claim)`; `session: <s> (arg|env)`

## Lines and files

Reads: journal `verified` (Slice, Commit, Attempt), `verify-pending` (Slice,
Commit, TS), `oracle` and `verify-error` (Slice, Commit: the pending line's
answer), `claim` and `release` (Session, Slice), `publish-done`; `ticket.yaml`
`blocked_by`; `slices.yaml` and slice states. A `verify-pending` line is pending
until a later `oracle` or `verify-error` line has the same Commit and Slice.
Writes: `projects.yaml` (locked, atomic, through `UpdateMachine`) and the new
`<jig home>/ignored.yaml` (`home.IgnoredPath`; `project.LoadIgnored`, `Ignore`,
`Unignore`, `IsIgnored`; locked and atomic). No journal or ledger line, no store
or repo write.

## Decisions

- **One source of truth for readiness.** `internal/ready` holds
  `ComputeReady` (frontier's `computeFrontier`, exported) and `Schedule`
  (copied, with `Batches` naming each batch's repo) and the workspace-to-repo
  map. `ready.Place` gives a single-repo project every workspace (the
  frontier's rule) and, with several repos, assigns a workspace to the first
  repo, in project order, whose manifest (`.claude/jig.yaml` or the detected
  `root`, read from the mapped clone) declares it; a workspace nobody declares
  is `?` and is noted. `frontier` is untouched (D13 deletes its copies).
- **Ticket readiness** (`ready.Tickets`): `done` (publish-done), `blocked`,
  `new` (no slices), `ready` (a ready slice), `green` (all green, unpublished),
  else `active`. `stacked` blockers wait for `publish-done` like `merged` ones:
  the brief's rule. ADR 0010 lets a stacked child start once its parent's gate
  is clean, but says enforcement is out of scope; that refinement is left out.
- **Overlap** is computed per repo of the project that has a mapped clone: local
  branches (`for-each-ref refs/heads`) that bind a ticket, the diff from the
  merge base with the target (or `origin/<target>`) to each branch with
  `gitx.MergeBase` + `gitx.DiffNameOnly` (the content of
  `git diff --name-only <target>...<b>`), and only when two different tickets
  have branches in the repo. A repo with no clone here is skipped.
- **Pending verifications are named by `here` itself** (`verificationsIn` in
  here.go), though D6 owns `here_verify.go` and `journal.Pending`. The block is
  `pending_verifications`, the JSON key the same; D6 can take it over by
  deleting that block and registering a section, or leave it.
- `distribution` is echoed from the marker, not interpreted.
- `jig here`'s ticket must exist: a positional that names none is refused; one
  bound by the branch always exists.

## Deviations from the brief

- `locate.Opts` gains `StoreOnly`, and `locate.ErrNotImplemented` is gone (it
  existed only for the stub). Both are in D3's own package.
- A clone of a mapped repo found by remote is mapped only when the repo has no
  live clone. The brief's `TestHereFreshCloneByRemote` ("projects.yaml now maps
  it") is built on a machine that knows the project and its store but not the
  repo's clone; replacing a live mapping would make two clones fight over one
  name on every `jig here`.
- The sibling store of `jig init --standalone` is still found without a map entry
  (the old `project.Resolve` last resort); the brief's order has no step for it,
  so it sits with the store directory step.
- `internal/project` gains `ignored.go` and `internal/home` gains `ignored.go`
  for `jig ignore`; the brief leaves the list's home open.
- `testdata/fixture/second-repo/` and `internal/fixture` `Opts.SecondRepo` (with
  `Fixture.SecondRepoDir` and `SecondRepoRemote`): the second repo has one
  workspace, `gamma`, project.yaml lists it second, and ticket JIG-1 gains slice
  `e` (gamma, no blockers). The base fixture is byte-for-byte unchanged.
- No ledger or journal writes anywhere, so D4's session minting and D7's
  SessionStart are free to add them.

## ADR impact

ADR 0032 (D1) should say: Locate is the single resolution of a directory to a
project and its store (flag, marker, map by path, map by remote, store
directory, none); the machine map is written on the spot for a recognized clone
and never replaced while live; `jig ignore` is the person's veto; `jig here` is
silent outside projects so a hook can run it anywhere; readiness (`jig next`) is
a pure function of slices, their states and ticket blockers, shared with the
retiring frontier. `project.Resolve` has no caller left in `cmd/jig`; D17 and D13
can delete it with `resolveStorePath`.
