# D19: store commits authored by the person

Branch `dg/D19`, from the `digester` tip 26b5642 (S0b, S0a merged). No new verb,
no flag, no journal or ledger line. Every commit jig makes in a store is now
authored and committed by the identity git resolves in the store clone, and
`jig@invalid` is gone from the repo's Go code, tests included.

## Rules a later ticket must keep

- **Any new store commit site** (D2's writer branches and claims branch, D17's `init` and `share`) takes its author from `Store.identity()`: in process through `cp.repo.CommitAllAs(msg, s.identity)`, by the git program through `commitConfig(id, "commit", ...)`. Never a literal name or email, never `-c user.name=jig`. `lint/identity_test.go` fails on both spellings.
- **Resolve before writing.** A command that always commits and writes first (Claim, init, migrate) resolves the identity before its first write.
- **A command with nothing to commit needs no identity.** `Sync` and `Push` on a clean store, and every read-only verb, still work on a machine with no identity. The in-process path therefore asks only inside `CommitAllAs`, the git program's path only after `add -A` staged something. Do not move the lookup earlier: `git var` costs a process (about 0.37 s on this Windows host) and `Sync` runs at the start of every command.
- **The cache is per `Store` value.** A second `Store` for the same root resolves again; a changed `user.name` is picked up by the next command, not by the running one.
- **Env beats config.** Under `gittest.PinIdentity` (cmd/jig, verifydeliver, mirror, e2e, and now `internal/project`) store commits are authored `jig-fixture`. A test that asserts the person authored a commit sets `user.name` and `user.email` in the store clone and, in e2e, runs jig `withoutIdentity()`. The refusal test sets `git config user.useConfigOnly true`, because git otherwise synthesizes `user@host` on a CI host.

## Decisions

- **`git var GIT_AUTHOR_IDENT` only.** One identity serves author and committer, as the brief says; `GIT_COMMITTER_*` in the environment still wins for the committer, in process and by the git program alike.
- **`CommitAllAs` instead of resolving before `CommitAll`.** The brief's `CommitAll(msg, n, e)` would make every `Sync` pay a `git var` and refuse a clean store on an identity-less machine. `CommitAll` keeps its signature (many gitx tests call it).
- **`InitStandalone` resolves in the new store**, where the commit lands and where every later store commit resolves it, not in the product repo. A machine whose identity lives only in the product repo's local config is refused at init with the two global-config help lines; it would fail the next `ticket new` otherwise.
- **`migrate` has a `TestMain`** (`gittest.Run`) now: it had none, so its tests ran against the host's global git config, and `Apply` now needs an identity. `newV1GitStore` configures one in the store.
- **`internal/project` pins the identity** in `TestMain` (`gittest.PinIdentity`): `InitStandalone` makes a new repo with no config of its own, so a test cannot give it one.
- **The lint is Go-only.** `TestNoArtificialStoreIdentity` parses string literals in every `.go` file, tests included. `ARCHITECTURE.md` still names the old identity (below); D1 rewrites it.

## Deviations from the brief

- Extra tests beyond the three named: `TestInitStandaloneIdentity` (e2e: scaffold authored by the global identity; the refusal removes the dir), and the store, gitx, migrate and project unit tests below.
- `Store.identity()` is not the only call site: `migrate.Apply` and `project.InitStandalone` call `gitx.ResolveIdentity` directly, as decision 8 says ("resolve it in the target repo").
- `TestStoreCommitsCarryCloneIdentity` asserts `requeue` made at least one commit, not two: requeue does not sync first, so its push records the brief amendment together with the slice state.

## ADR impact

- **ADR 0011 (the store runs git in process):** the in-process commit still cannot read git config, so it takes its identity from one `git var` call, made on the first commit of a process. Say so where the ADR lists what the in-process path does not do itself.
- **ADR 0032:** state the rule "store history names the person": every store commit is authored and committed by the identity git resolves in the store clone; a clone with none is refused with `IDENTITY_REQUIRED`; jig has no identity of its own.

## CONTEXT.md, Truth repo (store) entry: sentence to append

> Every commit jig makes in the store is authored and committed by the person's own git identity, as git resolves it in the store clone (`user.name` and `user.email`, or the environment); a clone with none is refused with `IDENTITY_REQUIRED` and the two commands that set one, and jig never commits under a name of its own.
