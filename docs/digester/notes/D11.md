## The three conditions

All three are enforced notes (`Note.Enforce`): the core only tells a session with
a person at it, and holds an unattended one (an unattended `claim` line, or
`unattended: true` in the `jig.yaml` marker) back at Stop once per Ref. The
source acts on tool, prompt and stop events and stays silent at session end.

| Condition | Found when | Ref | Text (one line, to the session) |
|---|---|---|---|
| stall | the ticket journal has `StallAfter` (2) or more `oracle` lines of outcome `fail`, one slice, one non-empty `signature`, counted from the last `verified` or `requeue` line of the slice; the latest of them was written since the session began | `stall:<slice>:<sha12 of the signature>:<attempt of the latest failure>` | `slice a failed its oracle the same way 2 times (attempt 3, latest at <sha12>): <summary, 200 bytes>. A repeat is likely a misconception: change the approach before another attempt.` Unattended it adds: `The slice is marked stalled; run jig requeue T --slice a once the approach has changed.` |
| brief drift | a slice with a `verified` line (and no later `requeue` of it) cites in `from_brief` a hash that is no section hash of the current `brief.md` (`store.BriefSectionHashes`) | `brief:<sha12 of the sorted slice:hash pairs>` | `the brief changed under verified work: slice a cites 1 section the brief no longer has. jig requeue T --from-brief-diff queues it again.` |
| scope drift | the commit HEAD moved to during a tool call (`NoteCtx.Commit`) changed files outside every workspace path of the slices of the ticket, as the manifest of the repo around the event directory places them | `scope:<sha12 of the commit>` | `commit <sha12> changed 2 files outside every workspace the slices of T build in (alpha, beta): docs/a.md, go.mod. Keep a commit to those workspaces.` |

Details a later reader needs:

- **A stall is a fact of the session, its count is not.** The latest failure must
  be newer than the session start (`NoteCtx.Since`; a zero start admits nothing,
  the same rule as the built-in `verification` source), but the count runs over
  the whole journal since the last reset, so a session that continues a stalled
  slice and fails the same way once more is told it failed 3 times.
- **A repeat is a new stall.** The attempt is in the Ref, so a third failure with
  the same signature is a new note, a new `correction` line and (unattended) a new
  marking of the slice. This matters because a verify worker sets the slice back
  to `building` on every failure (decision 2 of the design): the stalled state
  lasts until the next verification, and a stall that goes on is marked again.
- **Marking the slice** (`Stalled`, unattended only, at the first fire of a Ref):
  `queued`, `building` and an empty state become `stalled` with `reason: stall`,
  `signature`, `stall_summary` and `attempts = max(attempts, the stall attempt)`,
  the shape the frontier stall leaves. `stalled` (the frontier attempt-cap, say),
  `green`, `needs-input` and `env-blocked` are left alone: they already say what the
  slice waits for. It is written under `Store.LockCheckpoint`, like the verify
  worker, and left in the store clone for the next checkpoint to push (a hook
  does not wait on the network). `jig requeue T --slice a` (D13 keeps it) takes it
  from there. It is written once per Ref: a session that claims the slice again
  is not stalled again until a new repeat.
- **Brief drift is a state, not an event**, so it has no `since` rule: any session
  on the ticket hears it once. The remedy is the existing
  `jig requeue T --from-brief-diff` (the criterion is the same, restricted here to
  verified slices); after it, the slice is no longer verified for this purpose.
  The hashes in `slices.yaml` stay the job of the planner: a slice rebuilt against
  the new brief whose `from_brief` was never refreshed drifts again (the same Ref,
  so a session hears it once; `jig validate` prints the hashes to paste).
- **Scope drift is judged against all slices**, as the brief says (outside every
  slice workspace path), not against the slice of the commit. A slice whose
  workspace the manifest of this repo does not have builds in another repo and is
  passed over; if no slice resolves, or a workspace is `.`, nothing is outside.
  The commit is compared with its first parent (`gitx.DiffNameOnly`, added,
  deleted, modified, type-changed, no renames); a root commit is not judged. The
  manifest is read from the working tree of the repo top level of the event
  directory.
- **Re-offering.** The core asks a source again at every event, and Stop is not a
  tool call (`Commit` is empty), so a scope drift would be gone by Stop. The
  `correction` line it wrote (session, files, the full text in `summary`) is what
  the source reads back: a `scope-drift` line of the same session, since its
  start, is offered again at later events. Stall and brief drift are derived
  again from the journal and the brief each time. The core delivers each Ref once
  per session and refuses for it once, whichever event offers it.
- **Firing.** A `correction` line is written the first time a Ref is found in the
  ticket journal (any session), so a second session that finds the same stall or
  drift hears it (the core delivers per session) without a second line. If the
  state or the line cannot be written, the fact is not returned and the next call
  finds it again (state first, so the retry loses nothing). Two hooks at the same
  instant can both find a Ref unfired and write two lines; nothing breaks.
- **A detector that fails** (a manifest that does not parse, a git error) costs
  only its own note: `Check` returns the other notes with the joined error, and
  the adapter logs it to `observe.log` and returns the notes, because the core
  drops the notes of a source that returns an error.

## Line shapes

Ticket journal (`journal.Append`, `ts` from `NoteCtx.Now`), one per fire:

```
{"event":"correction","outcome":"stall|brief-drift|scope-drift","ref":"<Ref>",
 "session":..,"agent"?:..,"harness":..,"provenance":"jig","summary":"<the note text, 600 bytes>",
 "slice"?, "commit"?, "signature"? (stall), "files"? (scope drift, at most 20)}
```

`slice` is the slice of the stall, the located slice for a scope drift, empty for a
brief drift. No `attempt` key, so the `NextAttempt` numbering is untouched. Nothing
else reads a `correction` line yet but the source itself. The ledger lines are the
core: `note-delivered` with outcome `tool`, `prompt` or `stop-block` and `ref` set
to the Ref.

## Decisions

- **Enforce is true for all three**, as the brief says; none of them is scoped to the
  slice the session works on (the built-in `verification` source does not scope
  either: they are ticket facts).
- **The check is `internal/correct.Check`, not the source itself**, so the decisions
  have no dependency on the hook core and D14 (MCP) or a doctor can call them. The
  adapter only converts types and logs.
- **Equal signature, not equal commit**: two failures at one commit (a `--rerun`)
  count as two, as the frontier stall counter counted. A rerun that fails the same
  way is no progress either.
- **Oracle lines without a `signature`** (the frontier lines of a builder) never count.

  a file outside the workspaces of the fixture (`alpha`, `beta`) now gets a scope
  note in the hook output**, and, under the unattended marker, one Stop refusal for
  it. D13 `TestDigesterFlow`: the fixture scenario patches stay inside `alpha`
  and `beta`, so the flow is silent; a test commit of `notes/x.txt` or a root file is not.
- **D12** (spend): register beside this one; the sources run in name order
  (`answer`, `correction`, `spend`, `verification`) and share nothing.
- **D13**: the unattended Stop for a publish-ready ticket can rely on a stalled
  slice being marked `stalled` / `stall` by the time the session wants to stop (the
  Stop that finds a repeat refuses once for it); `jig requeue T --slice` is the
  remedy named in the text.
- **D1 / docs**: `correction` is in the journal-event list of `internal/journal/events.go`
  already (S0b); this ticket is its only writer.

## ADR impact (for D1)

ADR 0032 can say: the session is corrected from facts the journal already holds, not
from a second record: a repeated failure signature (a stall), a brief whose sections
no longer match what verified slices were cut from, and a commit outside every
slice workspace. Each is told to the session at its next tool call or prompt, once,
recorded as a `correction` line the first time it is found, and refused for once at
Stop when the session is unattended; an unattended stall also marks the slice
stalled so that `jig requeue --slice` is a real remedy. Nothing blocks a session
with a person at it.
