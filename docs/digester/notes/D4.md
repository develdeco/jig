# D4: the sessions ledger

Branch `dg/D4`, from the `digester` tip 26b5642 (S0b and S0a merged). Session
records on the machine ledger: written by four `jig session` verbs and by
`jig here` when it has to mint, read back by `ledger.Sessions`. Nothing is
stored per session; the ledger lines are the record, so a session started by
one process is listed by another.

## Verbs and flags

All four are registered in `cmd/jig/session.go`, Order 340 to 343, as two-word
verbs. `jig session` alone is an unknown command (S0a's rule for two-word
names); `jig session <verb> -h` prints the flags. None takes a positional
argument: one is refused with `VALIDATION_ERROR` (exit 2), because
`jig session end s1` would otherwise end whatever `JIG_SESSION` names.

| Verb | Flags | What it does |
|---|---|---|
| `session start` | `--session --harness --agent --model --effort --cwd` | one `session-start` line. Id: flag, else `JIG_SESSION`, else `ledger.MintID()`. `--cwd` defaults to the working directory (relative values resolve against it). Starting an id already in the ledger resumes it (a new line; clears `ended`). |
| `session touch` | `--session` | one `session-touch` line. Id: flag, else `JIG_SESSION`. |
| `session end` | `--session` | one `session-end` line. Ending an ended session writes nothing and prints the first end stamp (exit 0). |
| `session list` | `--all --json` | live sessions, most recently seen first; `--all` adds ended ones; `--json` prints a JSON array (`[]` when none) of `ledger.Session`. |

Output, in jig's register: `start` prints `session:` (id, then harness, agent,
model, effort, cwd when set, then started) and one help line; `touch` prints
`session:` id and last_seen; `end` prints `session:` id and ended; `list`
prints `sessions[N]{id,harness,ticket,slice,last_seen,ended,cwd}:` then a help
line. Stamps are RFC 3339 with nanoseconds (`ledger.Stamp`), so axi quotes them.

Exit codes and errors: 0 on success; `VALIDATION_ERROR` (2) for a missing id or
a stray positional; `SESSION_NOT_FOUND` (1) when touch or end names an id the
ledger has no record of; `SESSION_ENDED` (1) when touch names an ended session
(its help says to `session start` it again); `LEDGER_LOCKED` (1) from the ledger.
Touch and end read the whole ledger once to check the id; they are not the
per-tool-call path (that is `ledger.Append` from the observe hook).

## `jig here` session section

`cmd/jig/here_session.go` registers a here section: `Name: "session"`,
`Order: 340`, with both `Blocks` and `JSON`.

- It mints only when `Where.How` is neither empty nor `locate.HowNone` and
  `Where.Session` is empty. Then it writes a `session-start` line (cwd = `Where.Cwd`,
  clone = `Where.RepoDir`, ticket = `Where.Ticket`, slice = `Where.Slice`, stamped by
  `env.now`) and returns the block
  ```
  session:
    id: s-1a2b3c4d5e6f
    how: minted
    env: JIG_SESSION=s-1a2b3c4d5e6f
  ```
  and for `--json` the object `{"id": ..., "how": "minted"}`.
- A given session (`--session` or `JIG_SESSION`, so `Where.Session` set), a
  directory in no project, and an unset `hereCtx.JigHome` give: nothing, nothing,
  and an error (never a ledger under the working directory). A given or absent
  session returns no blocks and a nil JSON value; D3 owns how it shows
  `Where.Session` and `Where.SessionHow`, this section prints only what it created.
- Each `jig here` without a session mints a new one. That is the point (the
  caller gets an id to pin with `JIG_SESSION`), and also why a harness hook must
  pass the session it has, as D7's SessionStart does.
- It does not Sync, Push or touch a repo; the one write is the ledger line.

## Ledger shapes (`internal/ledger/sessions.go`)

All are `journal.Line` values in `ledger/ledger.ndjson`. The one key `journal.Line`
has no field for is `clone`, so session lines are written through a private
wrapper that embeds the Line and adds `clone` (omitempty). `ledger.Read` and
`ReadFrom` still return those lines as `journal.Line` and drop `clone`;
`ledger.Sessions` keeps it.

| Event | Keys | Writer |
|---|---|---|
| `session-start` | `session`, `agent?`, `harness?`, `cwd?`, `clone?`, `ticket`, `slice?`, `model?`, `effort?` | `ledger.StartSession`, `session start`, the here section |
| `session-touch` | the same | `ledger.TouchSession`, `session touch` |
| `session-end` | `session` | `ledger.EndSession`, `session end` |
| `tool` | `session`, `agent?`, `tool?`, `files?` (D7 writes it with `ledger.Append`) | read only here |
| `graph` | `ticket`, `slice?`, `session?`, `agent?`, `cwd?`, `files?`, `summary?` | `ledger.Graph` (for D8) |

(`ticket` has no omitempty on `journal.Line`, so a session line writes `"ticket":""`.)

API for later tickets:

- `type Session{ID, Harness string; Agents []string; Cwd, Clone, Ticket, Slice, Model, Effort, Started, LastSeen, Ended, LastTool string; Files []string}`
  with json keys `id harness agents cwd clone ticket slice model effort started last_seen ended last_tool files`
  (all but id, started, last_seen omitempty) and `Live() bool`.
- `type Registration{ID, Harness, Agent, Cwd, Clone, Ticket, Slice, Model, Effort string}`;
  `StartSession(root, at, Registration)`, `TouchSession(root, at, Registration)`,
  `EndSession(root, at, id)`. `at` zero means now. A field left empty is not written.
  An empty ID is refused before anything is written.
- `Sessions(root) (map[string]Session, error)`, `Recent(map) []Session` (newest `LastSeen`
  first, ties by id, stamps compared as instants), `MintID() string` (`s-` + 12 hex),
  `Stamp(time.Time) string` (the `ts` format), `Graph(root, journal.Line) error`
  (sets `Event`, requires `Ticket`, `TS` defaults to now).

Fold rules of `Sessions` (also in its doc comment): only `session-start`,
`session-touch`, `session-end` and `tool` lines with a session id count; lines
fold in file order, and `Started`/`LastSeen` are the earliest and latest stamp
whatever the file order (two processes stamp before they take the lock). Start
and touch replace harness, cwd, clone, model, effort with whichever they name;
a line that names a ticket replaces the slice with its own (so a slice never
outlives its ticket); a line that names only a slice replaces only that. Start
clears `ended` (a resume); touch and tool lines after an end do not. A tool
line sets `LastTool` and adds its `files` once each, and never changes the
session's cwd, clone, ticket or slice. Every line's `agent` joins `Agents` once.
A session whose first line is a tool line is still a session.

## For other tickets

- D3: call `hereSections()` with `hereCtx.JigHome` set and `Where.Session` filled
  from `--session` / `JIG_SESSION`, or the section mints a second id for a caller
  that has one. The section is silent for `How` empty or `none`, so D3 may call it
  either way. `TestHereMintsSession` (below) starts to run when `here` lands.
- D7: SessionStart writes `ledger.StartSession` (pass `Clone: Where.RepoDir`, the
  harness, model); tool events use `ledger.Append` with `EventTool`; SessionEnd uses
  `ledger.EndSession`; `ledger.TouchSession` carries a ticket or slice change. No
  `session touch` per tool call.
- D15/D16: `ledger.Sessions` is the liveness read. There is no staleness cutoff: a
  harness that dies without a SessionEnd leaves its session live in `session list`
  until someone ends it.
- D8: `ledger.Graph` for the graph line.

## Deviations from the brief

- **`TestHereMintsSession` skips until `jig here` exists.** The verb is D3's, in
  parallel, so the e2e test runs `jig here` and skips if the binary answers
  `unknown command "here"`. The section itself is covered in `cmd/jig`
  (`TestHereMintsSessionSection` and friends, no `here` needed). I ran the e2e
  test once against a temporary stand-in `here` verb (not committed) and it
  passed. After D3 and D4 are both in `digester`, run
  `go test ./e2e -run TestHereMintsSession -v` and check it is not skipped.
- **`internal/ledger/ledger.go` edited** (S0b's file, not on the do-not-touch list):
  `Append` now stamps and calls the new `appendValue` (the lock-and-write part, for
  the wrapper that carries `clone`); `parseLine` calls the new `decodeLine`;
  `Stamp` is exported. No behavior change; the S0b tests pass untouched.
- **`clone` rides beside `journal.Line`** rather than in it, since `journal.Line` is
  S0's. One more field in `Line` would remove the wrapper; D1 or a later ticket may
  prefer that.
- Exports beyond the brief: `Registration`, `StartSession`, `TouchSession`,
  `EndSession`, `Recent`, `Stamp`, `Session.Live`.
- `session start` records only what it is given. It does not call `locate.Locate`
  (a stub until D3), so ticket, slice and clone are filled by the here section and
  by D7 through `Registration`, not by the verb.

## ADR impact

None of its own. ADR 0032 can say: the sessions are a fold of the machine ledger
(machine-local, never in a store), keyed by the harness's session id or a minted
`s-<12 hex>`; liveness is "no `session-end` yet".
