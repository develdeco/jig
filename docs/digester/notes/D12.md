# D12: cost as records

Branch `dg/D12`, from the `digester` tip 2c3c35e (S0b, S0a, D7 and the rest
merged); the last `digester` merge into the branch is bdd8129 (D17). Spend and
budgets are records: a `spend` line in the ticket journal per session, a
`budget.yaml` in the ticket folder. Both are shown in `jig status`, and a ticket
near or over its budget is told to the person (Stop) and the model (next prompt
or tool call). Nothing is ever stopped.

## Verb

```
jig budget [<ticket>] [--tokens N] [--usd D] [--default] [--store p] [--project n]
```

Order 390, not hidden. The ticket is the positional one or the one the branch
binds (`resolveWork`). `--tokens` takes `5000000`, `5M`, `1.5m`, `200k`, `2G`;
`--usd` takes `20`, `12.50`, `$12.50`; `0` takes a limit away.

- With a flag: records `tickets/<id>/budget.yaml` (keys `tokens`, `usd`, each
  omitted when zero), with `Store.Sync` before and `Store.Push("<id>: budget")`
  after, like `jig note`. A limit not named keeps its value. A ticket with no
  record starts from the project default (the nearest `jig.yaml` marker's
  `budget`, looked up from the working directory, the repo and the project
  root), so `--usd 3` in a project defaulting to 2M tokens gives both.
  `--default` records the project default as it is (a VALIDATION_ERROR, exit 2,
  when the project has none); flags given with it win.
- Without a flag: shows the budget (a `budget:` block with `ticket`, `tokens`,
  `usd`, `source`) and the spend block. `source` is `ticket`, `ticket (none on
  purpose)` (an empty record), `project default (not yet recorded on the
  ticket)` or `none`.
- A budget of no limit is still written, as an empty file: "no budget on
  purpose", which the hook leaves alone (below).

## Record shapes

**`spend` journal line** (ticket journal, not the ledger), written by the note
source at Stop and SessionEnd when the session total changed:

```json
{"ts":..,"ticket":"JIG-1","slice":"a","event":"spend","session":"s-1","harness":"claude",
 "model":"claude-sonnet-4-5-20250929","provenance":"jig",
 "spend":{"input":1600,"output":1000,"cache_read":11000,"cache_write":900,"usd":0.026475},
 "summary":"unpriced: claude-fable-5"}
```

It is cumulative: the whole spend of the session so far. `slice` is where the
session was; `model` lists the models, comma separated; `summary` is present
only when a model has no price (`unpriced: a,b`). `Latest` takes the newest line
per session by stamp (file order when stamps do not parse), `FromLines` adds the
latest lines. A session with no id uses the transcript file name.

**`budget.yaml`**: `tokens: 5000000`, `usd: 20` (project.Budget as it is).

**Status** block, present once a ticket has spend lines or a budget with a
limit, absent before (so every existing status golden is untouched):

```
spend:
  sessions: 2
  tokens: 31200000        # input + output + cache_write + cache_read
  input: 162
  output: 429129
  cache_write: 1073306
  cache_read: 29664647
  usd: 12.34
  budget_tokens: 5000000  # only the limits that are set
  budget_usd: 10.00
  budget: over            # none | ok | near (>= 80% of a limit) | over (> a limit)
  unpriced: claude-fable-5
```

## The note source

`spend.Notes`, at every tool, prompt, stop and session-end event of a session
on a ticket in a store that is here:

- **Stop, SessionEnd**: read `Event.Transcript`, append the spend line when it
  differs from the latest of the session (counts, dollars, models). The first
  time it records spend for a ticket with no `budget.yaml`, it records the
  project default (the marker `budget`) as the ticket's, so status and the notes
  read one record. An empty file is a record: a budget cleared on purpose is
  not seeded again. Tool and prompt events write nothing.
- **Every event but session-end**: holds the ticket spend (the latest line of
  each session, including the one just written) against `budget.yaml`. At 80%
  of a limit or more it returns one note (`JIG-1 has used 85% of its spend
  budget: 17k of 20k tokens, $0.03 of $5.00 (1 session). Jig only reports
  spend; it stops nothing.`); past a limit the same shape with `is over its
  spend budget`. `Enforce` is never set. The Ref is `spend:<ticket>:<near|over>:
  <tokens limit>:<usd limit>`, so a state is told to a session once, and a
  budget raised and then passed again is news. A ticket with no budget record
  says nothing.

So Stop is silent under 80%; the person sees the note at the first Stop that
finds the state, and the model hears it at its next prompt or tool call, once
(`note-delivered`).

## Decisions

- **Dedupe by message id.** Claude Code writes one transcript line per content
  block of a message, each with the usage of the whole message: a real
  271-line transcript held 81 messages. Lines are merged by `message.id` (else
  `requestId`), taking the largest of each count; summing lines would overcount
  about 3x. Checked against an independent sum over two real transcripts (exact).
- **Only the lines of the session.** A resumed Claude session writes a new
  transcript that begins with the lines of the earlier session, keeping that
  session `sessionId` (seen on this machine). Lines with another session id are
  left out: they are in the spend line of that session. Lines with no
  `sessionId` count.
- **Subagents.** Their usage is in `<transcript minus .jsonl>/subagents/*.jsonl`
  (seen on this machine: same `sessionId`, no id overlap with the main file) and
  is counted with the session. `workflows/` is not read.
- **Tokens = input + output + cache write + cache read.** The breakdown is
  always shown. Cache reads dominate real sessions (a 287M-token session on this
  machine was 275M cache reads), so a token budget wants a large number; a
  budget on the first three is a one-line change in `Totals.Tokens`.
- **Dollars are list prices, and honest about gaps.** A `costUSD` on a
  transcript line wins when a version writes one. Otherwise the built-in table
  (opus 4, 4.1, 4.5, 3; sonnet 3.5, 3.7, 4, 4.5; haiku 3, 3.5, 4.5; the 1 hour
  cache write priced apart from the 5 minute one, from `usage.cache_creation`)
  and `<jig home>/prices.yaml` (below). A model in neither is **unpriced**: its
  tokens count, its dollars do not, and status, the spend line and the note say
  so. The models on this machine today (`claude-opus-5`, `claude-fable-5`,
  `claude-sonnet-5`) are all unpriced until they are put in `prices.yaml`.
- **The project default is recorded, not looked up.** `statusSection.Blocks`
  has no env and no directory, so status cannot find a marker. The first
  recorded spend (or `jig budget --default`) copies the marker budget into the
  ticket. A marker edited later does not change a ticket that has a record.
- **Pre-filter.** A transcript line is parsed only if it contains `"usage"`: a
  4000-line session transcript with 275M tokens reads in 120 ms.
- **Nothing on a missing transcript.** No path, a file not there yet, a harness
  whose transcript is not Claude JSONL (no usage keys): no line, no error.

## Deviations from the brief

- **`<jig home>/prices.yaml`** (not in the brief): without it `--usd` cannot
  work on the models in use. Format: a model id (date and `[1m]` suffixes
  ignored) to `input` and `output` (required, USD per million tokens), and
  `cache_write`, `cache_write_1h`, `cache_read` (default 1.25x, 2x and 0.1x the
  input rate). A file that does not parse adds no prices (the models show as
  unpriced); it is not an error of the hook.
- **`jig budget` shows** with no flag, and has `--default`: the brief names only
  the setting form.
- The logic of the note source is in `internal/spend/notes.go`, not in
  `cmd/jig/observe_spend.go`, so it is tested with a `NoteCtx` and no process.
- The Write and Edit tools refused paths in this worktree; every file was
  written through the shell.

## Limits

- Spend is read at Stop and SessionEnd only (the brief): a single long turn
  with no Stop is not metered until it ends. A write throttled to every few
  minutes at tool events would close that.
- `usage.iterations` (server-side compaction, advisors) is not read, the
  top-level usage is. The long-context premium tier is not priced.
- Codex, Gemini, Cursor and Copilot transcripts are not Claude JSONL: they
  produce no spend line.
- A session with no id and no transcript path records nothing.

## ADR impact (for D1)

ADR 0032 can say: cost is two records, a cumulative per-session `spend` line in
the ticket journal (summed from the transcript at Stop and SessionEnd) and a
per-ticket `budget.yaml` seeded from the `jig.yaml` budget of the project. The
budget is advice (a note, a status block) and is never enforced, so no session
is held back for money. Dollars are list prices, with the models that have none
named and not guessed.
