# D8: `jig claim`, `context`, `ask`, `answer`, `note`

Branch `dg/D8`, from the `digester` tip 45bbe97 (S0, D3, D4, D5.1 merged), then
merged with 4e8e648 (D6, D19) and 877d9d4 (D5.2). What `slice.json` carried when jig dispatched a
builder is now pulled: `jig context`. A session takes a slice with `jig claim`,
asks the person with `jig ask`, the person answers with `jig answer`, and either
leaves a `jig note`. The resume text of `jig status` names `jig answer`.

## Verbs

All five are registered from their own file (`claim.go`, `context.go`, `ask.go`,
`answer.go`, `note.go`), Orders 310 to 314. Every one takes `--store` and
`--project` (the house flags, not in the brief's table) and finds the ticket,
slice and session the way `jig here` does, through `locate.Locate` (`work.go`,
`resolveWork`): ticket = the positional, else the one the branch binds; slice =
`--slice`, `JIG_SLICE`, else the slice of the session's latest unreleased
claim; session = `--session`, else `JIG_SESSION`. A positional that is a ticket
id (`store.BranchLeadID(p) == p`) and comes first is the ticket; the rest is text
joined with spaces; a bare `--` makes everything after it text, so a note may
start with a dash.

| Verb | Flags | Exit |
|---|---|---|
| `claim [T]` | `--slice --unattended --take --release --session` | 0; 1 for a refused claim (`CLAIM_*`, `SLICE_HELD`, `SLICE_GREEN`); 2 for no ticket or no slice; `SLICE_NOT_FOUND` 1 |
| `context [T]` | `--slice --json` | 0; the same refusals as the others for ticket and slice |
| `ask [T] <text...>` | `--slice --wait --timeout --session` | 0 asked or answered; 2 `NEEDS_INPUT` when `--wait` ran out (the question stays open); 130 interrupted; 1 `QUESTION_SUPERSEDED` |
| `answer [T] <qid> <text...>` | hidden `--as person\|agent` | 0; `QUESTION_NOT_OPEN` 1; unknown question 2 |
| `note [T] <text...>` | `--slice --session` | 0; a note over 2000 bytes or empty is 2 |

**claim.** `--slice` is required unless `JIG_SLICE` or an earlier claim names it
(`VALIDATION_ERROR` listing the slices otherwise). Output: a `claim:` block
(`ticket slice result state session branch start took_over_from`), a
`warnings[N]{code,message,help}` table when the claim went through with
conditions unmet, and one help line. `result` is `claimed`, `already-claimed` (the
same session claiming again: no new line, the state is still made building if it
is not), `taken-over` (`--take` over another session's claim; `took_over_from` names
it) or `released`/`not-claimed` for `--release`.

- Conditions (checked for the ticket, in this order; each one unmet is reported):
  `CLAIM_BLOCKED_MERGED` (a blocker of kind merged, or no kind, has no `publish-done`
  line in its journal, or has a `pr` line with a `url` that `repohost.PRMerged` says
  is not merged; a host that cannot tell blocks nothing), `CLAIM_STACKED_PARENT_NOT_CLEAN`
  (a stacked blocker whose `latestGateRound` has no round, or a verdict other than
  `clean`), `CLAIM_NOT_APPROVED` (no `approval.yaml`, or its `brief_sha256` is not the
  `BriefSHA256` now; a ticket with no brief.md has nothing to approve).
- Unattended is `--unattended` or a `jig.yaml` marker with `unattended: true` found
  walking up from the working directory. Unattended, any unmet condition refuses
  the claim: exit 1, the first condition's code, every message in `error:`, nothing
  written. Otherwise they print as `warnings` and the claim goes through.
- `SLICE_HELD`: another session's claim line (not released since) holds the slice;
  `--take` is the way past, in both modes. A claim line with no session counts as a
  session of its own ("a session with no id"). Not in the brief: `--take` needed a
  meaning before D2, and two sessions on one slice is the thing a claim exists to
  stop. D2 adds its driver check beside this one and shares `--take`.
- `SLICE_GREEN`: a green slice is not claimable.
- State (`slice_moves.go`, one function per move, table-tested): a claim makes the
  slice building from queued, building, stalled or env-blocked (clearing reason,
  signature and stall summary, as every route out of a stall does); green is refused;
  a `needs-input` slice stays parked, the claim only records the holder, so the
  answer later finds it claimed and sends it to building.
- Start sha: `start.<repo>.sha` is written when absent: the merge base of HEAD (of
  the work tree the command runs in, else the clone) and `refs/remotes/origin/<target>`,
  else the local `<target>` (a fixture clone never fetched, so has no origin ref);
  nothing when neither resolves or the command runs outside a repo. `<repo>` is the
  one locate found, `<target>` its project.yaml `target:` (main by default).
- `--release`: queued again unless green or parked; a `release` line when anything held the
  slice or changed; `not-claimed` and no write when neither.
- The claim line's `Agent` is empty: the CLI has no agent id (D7's ledger tool records
  carry it). With no session id the help says to set `JIG_SESSION`.

**context.** `slicectx.Build` then `Context.Blocks()`, or `--json` (one line, the
`Context` struct). Text blocks, empty ones left out: `context:` (ticket, title, slice,
goal, workspace, oracle, oracle_command, env, state, blocked_by, attempt, oracle_seconds,
brief, intent, stale_brief_sections), `brief_sections[N]:` (each section as indented
markdown with its `## heading`), `seams:` (the brief's `## Seams` when the slice does
not list it in `from_brief`), `earlier_slices[N]{slice,commits,files}`,
`failed_attempts[N]{attempt,commit,summary}`, `related[N]{file,symbols}`,
`questions[N]{id,status,question,answer,provenance}`, `notes[N]{ts,slice,session,note}`,
then help. It never syncs and never writes the store. See `internal/slicectx` below.

**ask.** Writes the question (`Store.AddQuestion`: id and file under one lock), parks
the slice (`askedState`: queued, building or already needs-input become `needs-input`
on the new question; green, stalled and env-blocked keep their state), appends the
`question` line and pushes, then, with `--wait`, waits. Output without `--wait`:
`asked:` (ticket, slice, question, state) and a help line. `--wait` reads the question in
the store every 250 ms and syncs the store every 5 s; an answer given here shows at
once, one given elsewhere with the next sync. A failed sync does not end the wait; it
is named if the wait times out. It prints `answer:` (ticket, slice, question,
`provenance`), `text:` and the text indented, and writes a ledger `note-delivered`
line so a hook does not hand the session the same answer again. `--timeout` is 10m
by default, 0 for no limit. Without text, `--wait` waits on the slice's latest open question
(none: `VALIDATION_ERROR`), which is how a timed-out wait is resumed.

**answer.** Syncs, then `Store.AnswerAs` (the question file gets `status: answered`
and `provenance:`), then the slice moves (`answeredState`: a parked slice goes to
`building` if an unreleased claim holds it, else `queued`, clearing the question; while
another question of the slice is still open it stays `needs-input` on that one; a slice
not parked is left alone), the `answer` line, and a push. Provenance: `--as`, else
`person` when stdin is a terminal, else `agent`. Output `answered:` (ticket, question,
slice, provenance, state).

**note.** A `note` line on the slice (or the ticket with no slice), pushed. Text is the
`summary` of the line, at most 2000 bytes (the journal is read whole by every command);
`ref` is the first 12 hex of sha256(ticket, slice, text). Provenance as for answer.
Output `noted:` (ticket, slice, note).

## Line shapes

Journal (`journal.Append`, `ts` is nanosecond RFC 3339 from `env.now`):

| Event | Fields set | Writer |
|---|---|---|
| `claim` | `slice`, `session`, `unattended` (true when unattended), `branch` | claim |
| `release` | `slice`, `session`, `branch` | claim --release |
| `question` | `slice`, `session`, `ref` (q-001), `provenance: agent`, `summary` (text, one line, at most 600 bytes) | ask |
| `answer` | `slice`, `session` (the answerer's), `ref`, `provenance` (person or agent), `summary` (as above) | answer |
| `note` | `slice` (empty for the ticket), `session`, `ref` (fingerprint), `provenance`, `summary` (the text, at most 2000 bytes) | note |

The `question` and `answer` events the frontier writes (`slice`, `outcome`, `attempt`) are unchanged
and read as before; the new fields only add. Ledger: `graph` (via `ledger.Graph`) from
context: `ticket slice session cwd seconds outcome` (`pass`, or `fail: <reason>`) and `files` (the
related files); `note-delivered` from `ask --wait`: `ticket slice session ref provenance`.
Store files: `start.<repo>.sha`, `slices/<id>.state`, `questions/q-NNN.md` (front matter gains
`provenance:` when the question was answered with one; absent otherwise, so old files read as before).

`D7` (Stop and the next prompt) finds an answer for a session as: a `question` line with that
session and `ref` q, the question file answered, and no ledger `note-delivered` line for that
session and `ref`. `ask --wait` writes that delivery line itself; a hook that delivers should too.

## Changes outside the five verbs

- `internal/store/question.go`: `Question.Provenance`, `AnswerAs`, `AddQuestion`, `ReadQuestion`
  (`Answer` is `AnswerAs` with no provenance). Every read of a question file goes through
  `readFile` (`internal/store/read.go`, `read_windows.go`, `read_other.go`): on Windows an open
  that meets the rename `AtomicWrite` replaces the file with fails with a sharing violation (or
  access denied while the old file is pending delete), so the read is retried 10 times with a
  50ms backoff, as `AtomicWrite` retries its rename. Without it a session waiting with
  `ask --wait` failed with `ERROR` when the person answered at the moment it polled. The other
  store readers (slice state, slices, approval, intent, ticket) still use `os.ReadFile` and can
  meet the same window; moving them to `readFile` is a one-line change each, left to the ticket
  that next owns them. `internal/store/brief.go`: `BriefSection`,
  `BriefSections` (heading, body, hash); `BriefSectionHashes` is built on it.
- `internal/repohost/merged.go`: `PRMerged(ghBin, env, url) (merged, known bool)`, `gh pr view <url> --json state`.
  D10 owns the rest of `repohost`; this is a file of its own.
- `internal/slicectx` (below), `skills/build/SKILL.md` (D13 appends the old dispatch prompt).
- `cmd/jig/status.go`: `resumeCommand` is `jig answer <T> <q> '<text>'`. Goldens and assertions
  that pinned the old text: `cmd/jig/main_test.go`, `cmd/jig/gate_test.go`, `e2e/e2e_test.go`,
  `e2e/testdata/golden/status-run1-parked.txt`. `jig run --answer` still works until D13; the
  hint of `jig requeue` (frontier/requeue.go) still names it.
- `cmd/jig/work.go` (`resolveWork`, `work.slice`, `work.buildDir`, `splitTicket`, `parseWithText`),
  `slice_moves.go` (the state moves), `claim_checks.go` (the three conditions), `ask_wait.go`.
  `work.go` is a base for the next verbs that act for a session in a slice (D9, D11, D14 may use it).

## internal/slicectx

`Build(Input) (Context, error)`; `Input{Store, Ticket, Slice, Repo, RepoDir, Graph, RecordGraph, Session}`.
- Brief sections: the sections of `brief.md` whose hash a `from_brief` entry names (a name that
  matches none is counted in `stale_brief_sections`), plus `## Seams` when not listed.
- Earlier slices: `journal.VerifiedSlices` order; for each, the commits of the clone since the
  ticket's `start.<repo>.sha` (else the latest 300) whose last paragraph has `Jig-Slice: <slice>`
  (one `git log --name-only` through gitx), with the union of their files, at most 50 and the
  rest counted. A slice none of whose commits the clone has is listed with the shas of its `verified`
  lines and no files.
- Oracle: the manifest of the work tree resolves the slice's oracle to `oracle_command` (empty when
  the manifest lacks the workspace); `journal.LastOracleSeconds` of that command and env.
  `attempt` is `journal.NextAttempt`.
- Failed attempts: the slice's `oracle` lines with outcome `fail`, the latest 8, with `summary`.
- Graph: when `graphify.Plane.Enabled()` (the project opted in and the binary is on PATH), it adds
  `/graphify-out/` to the clone's `info/exclude`, updates, queries the goal plus up to 20 files of the
  earlier slices, groups by file (25 files, 8 symbols), and records the ledger `graph` line. A failure
  leaves `related` empty. It runs on every call: as long as graphify takes (ADR 0026), so only
  projects that opted in pay it.
- Questions of the slice (any status, with answer and provenance); notes on the slice or the ticket (latest 20).

## Decisions

- `--take` has a meaning before D2 (the slice-level takeover above); D2 extends it to the driver.
- A needs-input slice is not made building by a claim; a green slice is refused. Both follow decision 2.
- `ask` cannot park a stalled, env-blocked or green slice; the question is recorded and the state kept.
- Notes appear in `jig context` (the brief's list did not name them); a note nobody can read is no note.
- `BriefSections` was added to the store rather than hashing in `slicectx`, so one function owns the
  rule that makes a section's hash.
- The poll is 250 ms against the local store and 5 s against the remote (the brief says poll every 5 s):
  a person answering on the same machine should not make the asker wait 5 s.

## Deviations from the brief

- `--store` and `--project` on all five; `SLICE_HELD`, `SLICE_GREEN`, `QUESTION_NOT_OPEN`,
  `QUESTION_SUPERSEDED`, `SLICE_NOT_FOUND` as codes the brief does not list.
- `claim` takes its unattended default from the `jig.yaml` marker as well as the flag (D7's Stop rule uses
  the same default).
- `ask` text is optional with `--wait`; `answer` takes the ticket optional (the first word being a question id).
- The Write and Edit tools refused paths in this worktree; files were written through the shell.

## ADR impact

ADR 0032 (D1) can say: the facts a builder needs are pulled (`jig context`), not pushed in a file
the dispatcher wrote; a claim is a journal line plus the slice state, refused unattended and warned
attended when the ticket is not ready to build (blockers merged, stacked parent clean, brief approved);
a question parks its slice and an answer, which names who it speaks for, sends it back to work; the
answer reaches the session by `ask --wait`, the Stop hook or its next prompt. ADR 0024, 0025 and 0026
(the oracle time, the earlier slices, the code graph) now describe `jig context`, not slice.json:
the content is the same, the trailer replaces the journal ranges as the way to find a slice's commits.
